# 문화시설 사이니지 관리 프로토타입

가상의 공공 문화시설 안내센터에서 이미지 게시를 연습하는 **작동형 UI/UX 프로토타입**입니다. 화면 배치, 화면 등록, 이미지 보관함, 재생 방식, 가상 미리보기, 상태·오류 복구를 한 흐름으로 만져 볼 수 있습니다.

> 이 화면은 설계 결정과 사용성 테스트를 위한 것입니다. 실제 운영 시스템이 아니며, 모든 장소·화면·직원·이미지·활동 기록은 예시입니다. 데이터는 서버로 전송되지 않습니다.

> 공개 데모(설치 없이 화면 보기): <https://toxicyou25-afk.github.io/GugakSignage/>

## 실행

별도 빌드나 패키지 설치 없이 정적 파일로 실행됩니다. 이 폴더에서 로컬 서버를 띄워 주세요.

```sh
cd prototype
python -m http.server 4173 --bind 127.0.0.1
```

브라우저에서 <http://127.0.0.1:4173/>을 엽니다. 저장소 루트에서는 다음 명령도 같습니다.

```sh
python -m http.server 4173 --directory prototype
```

`index.html`을 직접 열어도 화면은 보이지만, 같은 출처의 저장 공간을 일관되게 쓰기 위해 로컬 서버 실행을 권장합니다. 외부 CDN, 웹폰트, 이미지 호스팅, 분석 도구를 사용하지 않습니다.

## 화면과 경로

| 화면 | 경로 | 확인할 내용 |
|---|---|---|
| 홈 | `#/dashboard` | 장소 카드, 온라인/오프라인/오류 수, 다음 할 일, 최근 활동(감사 로그), 빈 상태 |
| 장소·배치 | `#/site/site-a` | 1대/가로/세로/격자/직접 배치, 드래그·리사이즈, 방향·해상도, 경고, 실행 취소, 화면 추가·해제 |
| 화면 등록 | `#/register` | 이 브라우저로 테스트, 6자리 확인 코드, 자동 찾기, 링크 등록, 등록 대기 → 승인 분리 |
| 이미지 보관함 | `#/library` | 파일 끌어다 놓기/선택, 실제 크기 읽기, 비율·잘림·안전 영역 확인, 사용처, 삭제 확인 |
| 재생 설정 | `#/playback` | 네 가지 재생 방식, 이미지 순서 드래그·위아래 버튼, 표시 시간, 화면별 시작·이동, 패턴 표, 비상 이미지 |
| 미리보기 | `#/preview` | 한 시간축의 가상 모니터, 재생·일시정지·시간 이동, 다음 전환, 오류 화면의 비상 이미지, 게시 확인 |
| 화면 상태 | `#/status` | 상태 문장, 필터, 아이콘+글자+색 배지, 원인·다음 행동, 다시 연결/테스트/로그 복사 |
| 첫 설정 | `#/setup` | 장소 → 화면 → 배치 → 이미지 → 재생 → 미리보기·게시의 6단계, 초안 저장·이어하기 |

## 6단계 첫 사용 흐름

1. 장소 이름과 운영 시간을 정합니다.
2. 화면 수를 고르고 자동으로 찾은 화면을 확인합니다.
3. 배치 방식과 화면 방향·해상도를 정합니다.
4. 보관함에서 이미지를 고르거나 JPEG·PNG·WebP 파일을 올립니다.
5. 재생 방식을 고르고 이미지 순서와 표시 시간, 비상 이미지를 정합니다.
6. 가상 모니터와 경고를 확인한 뒤 게시합니다.

각 단계는 자동 저장되며, 화면을 떠나도 홈의 초안 카드에서 이어서 할 수 있습니다. `초안 버리기`는 확인을 거칩니다.

## 시나리오 가이드

오른쪽 위 **시나리오**를 열어 모의 데이터를 바꿀 수 있습니다.

- 장소: `2곳` 또는 `빈 상태(0곳)`
- A 안내센터 화면 수: `1대 · 4대 · 6대` — B 안내센터는 2대로 유지
- 두 장소의 재생 이미지 수: `0장 · 1장 · 3장 · 8장`
- A 안내센터 재생 방식: `개별 재생 · 순환 동기화 · 동시 재생 · 통합 화면`

이 시나리오와 숫자는 여러 장소와 화면 구성을 설명하기 위한 가상 예시이며 실제 운영 구성을 뜻하지 않습니다.

시나리오를 적용하면 화면, 재생 순서, 올린 이미지, 초안이 **초기값으로 돌아갑니다.** 사용성 테스트 중에는 먼저 시나리오를 정한 뒤 이미지를 올리는 순서를 권장합니다. `처음 상태로 돌아가기`는 장소 2곳, A 4대, 이미지 3장, 순환 동기화로 되돌립니다.

등록 화면의 연습용 6자리 코드는 두 가지입니다.

- `482913`: 이미 자동으로 찾은 화면의 코드입니다. 넣으면 해당 대기 항목으로 이동합니다.
- `135790`: 새 대기 화면을 만듭니다. 코드 입력 뒤에도 바로 게시되지 않고 **승인 단계**가 남습니다.

`이 브라우저로 테스트`는 테스트 화면과 새 6자리 확인 코드를 보여 줍니다. `등록 대기로 보내기`를 누르면 대기 목록에 추가되고, 관리자가 이름과 방향을 확인한 뒤 승인합니다.

## 이번 프로토타입이 보여 주는 것

- **홈:** 장소별 화면 상태를 문장으로 먼저 읽고, 다음 할 일과 최근 감사 로그를 확인합니다.
- **배치:** 화면을 끌어 옮기고 오른쪽 아래 손잡이로 크기를 바꿉니다. 겹침, 빈 공간, 화면 밖, 오프라인, 비율 차이를 경고합니다. 키보드 방향키로 이동하고 `Alt`+방향키로 크기를 바꿀 수 있습니다. 드래그 중 `ESC`를 누르면 원래 배치로 돌아갑니다.
- **화면 등록:** 이 브라우저 테스트 → 등록 대기 → 관리자 승인의 2단계 흐름과 6자리 코드를 함께 보여 줍니다.
- **이미지:** File API로 실제 파일을 읽어 미리 보여 줍니다. 대상 모니터마다 비율이 맞는지, ‘맞추기’에서 여백이 생기는지, ‘채우기’에서 잘릴 수 있는지, 안전 영역이 어디인지 확인합니다.
- **재생:** 이미지 수와 화면 수가 달라도 시작 위치와 이동으로 배분합니다. 최소 공통 주기 표로 0·1·3·8장과 1·4·6대 조합을 확인할 수 있습니다.
- **미리보기:** 여러 모니터를 하나의 시간축으로 재생하고, 시간 이동·다음 전환·오류 화면의 비상 이미지 전환을 확인한 뒤 게시합니다.
- **상태:** `6대 중 3대 정상, 3대 확인 필요.`처럼 상태를 문장으로 먼저 제시한 뒤 배지, 원인, 다음 행동, 복구 버튼을 보여 줍니다.
- **감사·개인정보:** 화면 승인, 게시, 복구 기록은 이름과 작업 내용만 남깁니다. 개인 연락처를 입력하거나 저장하지 않습니다.

## 벤치마크 반영 내역

### 해외 UI 벤치마크 반영

- 이 브라우저로 테스트, 6자리 확인 코드, 자동 발견, 등록 대기와 승인을 분리했습니다.
- 대기 화면은 승인 전까지 배치에 연결되지 않는 흐름을 기본으로 하고, 이미 배치에 놓인 대기 화면은 승인 시 기존 슬롯에서 바로 온라인으로 바꿉니다.
- 게시 전 **비상 이미지**를 고르게 하고, 오류 화면은 미리보기에서 비상 이미지로 바뀝니다. 오프라인 화면은 설계 원칙대로 마지막 이미지를 유지합니다.
- 업로드와 이미지 상세에 대상 모니터별 비율·여백·잘림·안전 영역 경고를 넣었습니다.
- 이미지 수와 모니터 수가 다른 경우의 패턴 표와 한 시간축 사이트 미리보기를 공유 재생 로직으로 구현했습니다.
- 상태는 색만 쓰지 않고 아이콘·글자·문장으로 먼저 읽히게 했습니다.
- 용어를 **화면 / 모니터 / 장소 / 이미지 / 이미지 순서 / 재생 방식 / 미리보기 / 게시**로 맞추고, 이전 표현인 ‘송출’과 ‘콘텐츠’는 화면 문구에서 사용하지 않습니다.

### 국내·KRDS 벤치마크 반영

- 루트 글자 크기 17px, 본문 줄간격 165%, 핵심 대비 4.5:1 이상, UI 대비 3:1 이상을 확인했습니다.
- 주요 버튼·아이콘 버튼·탭·필터·선택 카드·드래그 핸들에 44px 이상 터치 영역을 적용했습니다.
- 모든 입력에 레이블을 두고, 오류 요약과 첫 오류 포커스를 구현했습니다. 저장·게시·오류 상태는 `aria-live`로 알립니다.
- 건너뛰기 링크, 보이는 포커스, 모달 포커스 트랩, `ESC` 닫기, 포커스 복귀를 구현했습니다.
- 이미지 순서 드래그에는 위/아래 버튼 대안이 있고, 배치 드래그는 `ESC`로 취소할 수 있습니다.
- 표에는 `caption`, `thead`, `th scope`를 사용하고, 768px에서는 상태 표를 카드형 행으로 바꿉니다.
- 한글은 `word-break: keep-all`, 긴 파일명·주소는 예외적으로 `overflow-wrap: anywhere`를 적용했습니다. 숫자는 `tabular-nums`입니다.
- KRDS 화면·코드·아이콘은 복제하지 않았습니다. 원본 CSS와 직접 만든 SVG 아이콘·예시 포스터만 사용했습니다.

## 디자인 결정

- **차분한 행정 화면:** 짙은 남색, 한지 베이지, 청자색, 주홍을 사용하고, 전통 문양을 직접 복제하지 않았습니다.
- **한 화면에 한 결정:** 배치, 이미지, 재생 방식, 미리보기를 별도 화면으로 나눴습니다.
- **원본 그래픽:** 로고·상용 아이콘·상용 화면을 쓰지 않고, 인라인 SVG 아이콘 30여 개와 예시 포스터 8장을 직접 만들었습니다.
- **정보 밀도:** 초보 사용자를 위해 큰 여백과 17px 본문을 쓰고, 관리용 표는 별도 탭·모달로 분리했습니다.
- **안전한 게시:** 이미지가 한 장도 없으면 게시 버튼을 막고, 비상 이미지가 없으면 경고합니다. 오프라인은 마지막 이미지를 유지하고, 오류는 비상 이미지로 대체하는 것으로 구분했습니다.
- **프로토타입 데이터:** 2개 장소, A 4대/B 2대, 이미지 3장, 순환 동기화를 기본으로 두었습니다. 시나리오를 바꾸면 모두 초기화됩니다.

## 접근성 확인

- 본문 17px · 줄간격 165% · `keep-all` · 숫자 `tabular-nums`
- 모든 입력에 레이블, 도움말, 오류 메시지 연결
- 오류 요약 표시 후 첫 오류로 포커스 이동
- 저장·게시·업로드·삭제·복구 결과를 `aria-live`로 알림
- `Tab`/`Shift+Tab` 포커스 이동, 건너뛰기 링크, 모달 트랩, `ESC` 닫기와 포커스 복귀
- 이미지 순서 위/아래 버튼, 배치 화면 방향키·`Alt`+방향키, 드래그 중 `ESC` 취소
- 상태 배지는 아이콘+글자+색을 함께 사용하고, 상태 문장을 먼저 표시
- 표의 `caption`·`thead`·`scope`, 768px 카드형 전환

## 알려진 한계

- 백엔드, 인증, 실제 네트워크 탐색, 실제 플레이어 제어가 없습니다. 자동 발견·승인·하트비트·복구는 모의 동작입니다.
- 모든 변경은 이 브라우저의 저장 공간에만 남습니다. 업로드 이미지는 data URL로 저장하므로 브라우저 저장 공간이 부족하면 새로 고침 뒤 사라질 수 있습니다. 파일당 8MB로 제한했습니다.
- 이미지 안전 영역은 자동 인식이 아니라 가장자리 10% 점선 안내입니다. 실제 문구·얼굴이 잘리는지는 사람이 확인해야 합니다.
- 로컬 이미지 미리보기와 규격 검사는 브라우저에서 읽을 수 있는 정적 JPEG·PNG·WebP만 지원합니다. GIF·동영상은 없습니다.
- `개별 재생`은 프로토타입에서 하나의 이미지 목록과 화면별 시작 위치·이동을 공유합니다. 운영 버전에서는 화면별 목록 분리가 필요할 수 있습니다.
- 베젤(화면 사이 간격)은 정규화된 배치 간격으로만 표현하며 실제 모니터 테두리 두께를 mm 단위로 보정하지 않습니다.
- 통합 화면은 이미지 한 장을 논리적 캔버스에 나누는 시뮬레이션이며, 실제 다중 창 렌더링은 아닙니다.
- 게시 버전, 승인자, 감사 로그는 로컬 모의 기록입니다. 실제 권한·서명·보존 정책은 서버 설계에서 정해야 합니다.
- A 안내센터 시나리오의 화면 수를 바꾸면 B 안내센터는 2대로 유지됩니다. 이 고정값은 테스트 편의를 위한 가정입니다.
- 드래그는 포인터·HTML5 드래그를 지원하는 데스크톱 브라우저에 최적화했습니다. 터치 환경에서는 위/아래 버튼과 `ESC` 취소를 대안으로 씁니다.

## 검증 방법

로컬 서버를 띄운 뒤 다음 명령으로 핵심 흐름을 검사할 수 있습니다.

```sh
cd prototype
npm install
npx playwright install chromium
npm run test:smoke
```

이미 설치된 Chromium을 쓰려면 다음처럼 실행 파일을 지정할 수 있습니다.

```sh
$env:PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH = 'C:\path\to\chrome.exe'
node tests/smoke.mjs
```

또는 서버와 페이지를 직접 확인할 수 있습니다.

```sh
curl.exe -I http://127.0.0.1:4173/
curl.exe http://127.0.0.1:4173/app.js | Select-String 'SPDX-License-Identifier'
```

확인한 결과(2026-11-24, Playwright 1.65.1 + Chromium 151 headless):

- 홈 → 장소 → 화면 등록 → 이미지 보관함 → 재생 → 미리보기 → 상태 경로가 모두 열렸습니다.
- 화면 배치 드래그·리사이즈, 키보드 이동, `ESC` 취소, 추가·해제·실행 취소가 동작했습니다.
- 이 브라우저 테스트 → 등록 대기 → 승인, 수동 6자리 코드 오류·대기 추가, 링크 복사가 동작했습니다.
- 로컬 PNG 업로드, 미리보기, 대상 모니터별 확인, 삭제 확인이 동작했습니다.
- 재생 순서 드래그·위아래 버튼·표시 시간 0초 경고·비상 이미지 선택·패턴 표가 동작했습니다.
- 미리보기 재생·일시정지·스크럽·오류 화면 비상 이미지·게시 확인이 동작했습니다.
- 상태 문장, 필터, 모달 포커스 트랩, `ESC` 복귀, 다시 연결이 동작했습니다.
- 초안 저장·나가기·이어하기·버리기가 동작했고, 새로 고침 후에도 상태가 남았습니다.
- 1280px와 768px에서 가로 스크롤이 생기지 않았고, 외부 네트워크 요청은 0건이었습니다.
