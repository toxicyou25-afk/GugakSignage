# UI·UX 설계 원칙과 화면 구조

작성 2026-11-24 / 벤치마킹 전 초안. 조사 결과로 검증·수정한다.

## 1. 목표

일반 행정·홍보 담당 직원이 **별도 매뉴얼 없이** 이미지 등록부터 실제 송출까지 끝낼 수 있게 한다. 기능을 많이 넣기보다 “다음에 무엇을 해야 하는지”가 항상 보이게 한다.

- 첫 사용자는 6단계 안내로 첫 송출을 완료한다.
- 반복 사용자는 대시보드에서 상태 확인과 이미지 교체만 한다.
- 오류가 나면 원인과 다음 행동을 쉬운 한국어로 보여준다.
- 키보드·화면 낭독기·고대비 환경에서도 핵심 업무를 할 수 있다.

## 2. 디자인 원칙

1. **한 화면에 한 가지 결정** — 배치, 이미지, 재생 방식, 미리보기를 한 화면에 섞지 않는다.
2. **다음 할 일이 보인다** — 대시보드와 각 단계에 “다음” 버튼과 남은 단계를 표시한다.
3. **쉬운 한국어** — “디스플레이”, “디바이스”, “플레이리스트”보다 “화면”, “모니터”, “이미지 순서”를 먼저 쓴다. 필요하면 괄호로 전문 용어를 병기한다.
4. **실수해도 되돌릴 수 있다** — 초안 저장, 게시 전 미리보기, 실행 취소, 삭제 확인을 제공한다.
5. **상태가 한눈에** — 온라인·오프라인·대기·오류를 색만이 아니라 아이콘과 글자로 표시한다.
6. **일관성** — 같은 행동은 같은 버튼 이름·위치·색을 쓴다. “송출”, “게시”, “저장”을 섞지 않는다.
7. **접근성** — 충분한 대비, 보이는 포커스, 키보드만으로 핵심 흐름 완료, 오류 요약과 `aria-live` 상태 알림.
8. **원본 디자인** — 상용 제품의 화면·아이콘·로고·독창적 배치를 복제하지 않는다. 패턴만 추상화해 참고한다.

## 3. 정보 구조

```text
홈
├─ 오늘의 송출 상태
├─ 장소 카드
├─ 다음 할 일
└─ 최근 활동

장소
├─ 장소 목록
└─ 장소 상세
   ├─ 모니터 배치
   ├─ 화면 목록·상태
   ├─ 재생 설정
   └─ 미리보기

콘텐츠
├─ 이미지 보관함
├─ 업로드·규격 검사
└─ 이미지 상세

재생
├─ 재생 방식(개별/순환/동시/통합)
├─ 이미지 순서·표시 시간
├─ 화면별 시작 위치·회전 방향
└─ 게시 이력

미리보기
├─ 가상 모니터
├─ 시간 이동·재생
└─ 경고·검사 결과

설정
├─ 사용자·권한
├─ 서버·백업
└─ 감사 로그
```

처음에는 상단 메뉴를 `홈 / 장소 / 콘텐츠 / 재생 / 미리보기` 5개로 제한하고, `설정`은 오른쪽 위 사용자 메뉴에 둔다. 모니터 등록과 상태는 `장소` 안에서 처리해 메뉴를 늘리지 않는다.

## 4. 첫 사용 6단계

| 단계 | 화면 | 사용자가 하는 일 | 시스템이 돕는 일 |
|---|---|---|---|
| 1 | 장소 만들기 | 이름·운영 시간 입력 | 템플릿(1대/가로/세로/격자) 제안 |
| 2 | 화면 등록 | 자동 발견된 화면 승인 또는 코드 입력 | 해상도·방향·브라우저 자동 표시 |
| 3 | 배치 정하기 | 1대·가로·세로·격자·직접 배치 선택, 드래그 | 겹침·빈 공간·화면 밖 경고 |
| 4 | 이미지 올리기 | 끌어다 놓기 또는 파일 선택 | 규격 검사, 비율 경고, 썸네일 |
| 5 | 재생 정하기 | 방식 선택, 순서·시간·시작 위치 설정 | 이미지 수/모니터 수 패턴 미리보기 |
| 6 | 미리보기·송출 | 가상 모니터로 재생, 게시 | 오류·오프라인·비율 경고, 게시 요약 |

- 각 단계는 저장 후 나중에 이어서 할 수 있다.
- 1~3단계는 장소를 만들 때 한 번, 4~6단계는 이미지가 바뀔 때 반복한다.
- “빠른 교체” 모드: 기존 장소에서 이미지 몇 장만 바꾸는 3단계 흐름(올리기 → 순서 확인 → 미리보기·송출)을 별도 제공한다.

## 5. 주요 화면

### 5.1 홈(대시보드)

- 상단: “오늘의 송출 상태” — 전체 화면 수, 온라인 수, 주의 필요 수.
- 장소 카드: 장소명, 모니터 수, 온라인/오프라인, 현재 이미지 썸네일, 마지막 게시 시각, `미리보기`·`이미지 바꾸기` 버튼.
- “다음 할 일” 카드: 오프라인 화면, 비율 경고, 게시되지 않은 초안, 새로 발견된 화면.
- “최근 활동”: 누가 언제 무엇을 게시/수정했는지.
- 빈 상태: “첫 장소를 만들어 보세요” + 6단계 중 1단계로 가는 큰 버튼.

### 5.2 장소 상세·배치

- 헤더: 장소명, `송출 중` 상태, 마지막 게시, `미리보기` 버튼.
- 배치 캔버스: 모니터를 사각형으로 표시. 각 사각형에 이름, 해상도, 방향, 온라인 상태.
- 도구 모음: `1대`, `가로`, `세로`, `격자`, `직접 배치`, `화면 추가`, 실행 취소/재실행, 확대/축소.
- 오른쪽 패널: 선택한 모니터의 이름, 해상도, 방향, 회전, 이미지 맞춤(contain/cover), 테스트 이미지.
- 드래그·리사이즈·스냅·정렬·키보드 미세 조정.
- 경고: 겹침, 빈 공간, 화면 밖, 해상도 불일치.

### 5.3 화면 등록

- `자동으로 찾기`: 같은 네트워크에서 등록을 기다리는 화면 목록. 각 항목에 6자리 확인 코드, IP, 해상도, 브라우저, `승인` 버튼.
- `코드로 등록`: 화면에 표시된 6자리 코드 입력.
- `링크로 등록`: 등록 URL 복사. 브라우저 저장소가 지워지는 환경에 적합.
- 승인 후: 장소·그룹 선택, 이름 입력, 방향 확인, 테스트 이미지 표시.
- capability 배지: `브라우저`, `화면 2대`, `다중 창`, `오프라인 캐시`, `구형 브라우저`.

### 5.4 콘텐츠 보관함

- 업로드 영역(드래그·파일 선택), 진행률, 중복 파일 안내.
- 카드/목록 보기: 썸네일, 파일명, 크기, 해상도, 비율, 사용 중인 장소, 업로드일.
- 이미지 상세: 가로/세로 미리보기, 안전 영역, 비율 경고, `다른 이미지로 바꾸기`, 사용처.
- 일괄 작업: 태그, 삭제(확인), 내려받기. 사용 중인 이미지는 삭제 전에 영향 범위 표시.

### 5.5 재생 편집

- 재생 방식 카드 4개: `개별 재생`, `순환 동기화`, `동시 재생`, `통합 화면`. 각 카드에 한 줄 설명과 작은 그림.
- 이미지 순서: 드래그 앤 드롭 목록. 썸네일, 이름, 표시 시간(초), 맞춤 방식, 전환.
- `자동 채우기`: 이미지 수와 모니터 수를 보고 시작 위치·회전 방향을 자동 배분.
- 패턴 미리보기: 모니터별로 1주기~LCM 주기까지 어떤 이미지가 나오는지 표로 표시.
- 경고: 이미지 없음, 이미지 부족, 같은 이미지 중복, 표시 시간 0, 합계 시간 불일치.

### 5.6 미리보기·시뮬레이션

- 가상 모니터 캔버스: 실제 배치 비율로 모니터를 그리고, 현재 이미지를 표시.
- 재생/일시정지, 시간 이동(스크럽), 배속, 다음 전환까지 남은 시간.
- 모드 전환, 가로/세로 전환, 기기 프레임 표시.
- 경고 패널: 오프라인, 비율 불일치, 겹침, 빈 슬롯, 이미지 없음.
- `이대로 송출` 버튼 → 게시 요약(장소, 모니터 수, 이미지 수, 모드, 버전) → 확인.

### 5.7 상태·오류

- 상태 배지: `온라인`, `오프라인`, `대기`, `오류`. 아이콘+글자+색.
- 화면 상세: 마지막 연결, 현재 이미지, 버전, 해상도, 방향, 네트워크, 오류 코드, 로그 복사.
- 오류 문장은 “원인 + 다음 행동” 형식. 예: “서버에 연결하지 못했습니다. 네트워크 케이블을 확인한 뒤 `다시 연결`을 눌러 주세요.”
- 복구 버튼: `다시 연결`, `테스트 이미지 보내기`, `플레이어 다시 시작`, `로그 복사`.
- 오프라인 화면은 마지막 콘텐츠를 계속 재생한다는 점을 화면에 표시한다.

## 6. 시각 디자인

- 분위기: 국악원의 차분한 이미지와 행정 서비스의 신뢰감. 전통 문양을 그대로 쓰지 않고, 색과 여백으로만 은은하게 표현한다.
- 색: 짙은 남색(주요 행동), 한지 베이지(배경), 청자색(보조), 주홍(경고/강조). 색만으로 상태를 구분하지 않는다.
- 글꼴: Noto Sans KR 또는 Pretendard(OFL) 중 라이선스가 명확한 것을 쓴다. 본문 16px 이상, 줄간격 1.6.
- 모서리·그림자: 과장하지 않고, 카드와 표를 구분하는 정도로만.
- 아이콘: 직접 만든 SVG 또는 Lucide(ISC) 등 라이선스가 명확한 세트. 상용 제품 아이콘을 복제하지 않는다.
- 화면 밀도: 초보 사용자를 위해 여백을 넉넉히. 관리자용 고밀도 표는 별도 보기로 제공.

## 7. 접근성·한글 가독성

- 본문 대비 4.5:1 이상, 큰 글자/UI 3:1 이상.
- 모든 입력에 레이블, 필수/선택 표시, 도움말 연결.
- 오류는 입력란 아래 + 상단 요약에 함께 표시하고, 첫 오류로 포커스 이동.
- 키보드만으로 업로드·순서 변경·미리보기·게시 가능. 드래그 앤 드롭에는 `위로/아래로` 버튼을 함께 제공.
- 포커스 링을 숨기지 않는다. 모달은 포커스 트랩, ESC 닫기.
- `aria-live`로 저장·게시·오류 상태를 알린다.
- 한글 줄바꿈은 `word-break: keep-all`, 긴 URL·파일명은 `overflow-wrap: anywhere`.
- 표는 헤더와 연결, 작은 화면에서는 카드로 전환.
- 색맹·저시력 사용자를 위해 상태 아이콘·문구를 병행한다.

## 8. 벤치마킹 조사 질문

조사 워커는 아래 질문에 제품별로 답한다.

1. 첫 로그인 후 무엇을 먼저 보여주는가? 빈 상태와 온보딩은 어떤가?
2. 장소·그룹·화면을 몇 단계로 만들 수 있는가? 용어는 쉬운가?
3. 화면 등록은 자동 발견인가, 코드/수동인가? 상태·해상도·방향을 어떻게 보여주는가?
4. 다중 모니터 배치는 격자·자유 배치·베젤 보정을 어떻게 지원하는가?
5. 이미지 업로드 시 규격·비율·용량을 어떻게 검사하고 안내하는가?
6. 드래그 앤 드롭 편집기는 학습 곡선이 어떤가? 실행 취소·스냅·미리보기가 있는가?
7. 재생목록·시간·모드를 어떻게 설정하는가? 이미지 수와 화면 수가 다를 때 어떻게 안내하는가?
8. 미리보기·시뮬레이션은 실제 송출과 얼마나 일치하는가?
9. 상태·오류·오프라인을 어떻게 보여주고, 복구 행동을 제공하는가?
10. 초보 사용자가 막히는 지점은 어디인가? 도움말·검색·템플릿이 있는가?

## 9. 저작권·라이선스 원칙

- 상용 제품의 화면·소스·아이콘·로고·독창적 디자인을 복제하지 않는다.
- 벤치마킹은 “정보 구조, 흐름, 용어, 피드백 패턴” 수준에서 추상화한다.
- 실제 화면 캡처는 조사 목적으로만 `artifacts/research/`에 두고, 저장소·배포물·공개 자료에 넣지 않는다.
- 오픈소스 코드·아이콘·폰트를 쓰면 LICENSE와 출처를 `docs/research/licenses.md`에 기록한다.
- KRDS를 참고하되, 구성 요소를 그대로 복제했다고 주장하지 않는다. 사용한 범위와 라이선스를 확인한다.
- 제품 이름·로고를 우리 제품에 쓰지 않는다. 화면의 예시 브랜드는 가상의 “국악원 사이니지”로 한다.

## 10. 프로토타입 범위

- 정적 HTML/CSS/JS 또는 가벼운 빌드. 백엔드 없이 mock 데이터로 동작.
- 화면: 홈, 장소 상세(배치), 화면 등록, 콘텐츠, 재생 편집, 미리보기, 상태·오류.
- 상호작용: 장소 추가, 화면 승인(모의), 이미지 업로드(File API 미리보기), 배치 드래그, 재생 순서 변경, 모드 전환, 미리보기 재생/스크럽, 게시 확인.
- 1대·4대·6대, 이미지 0·1·3·8장 시나리오를 전환해 볼 수 있게 한다.
- 키보드 포커스, 대비, 한국어 문구, 반응형을 확인한다.
- 실제 서비스에 쓰는 코드가 아니라 **의사결정용 작동 프로토타입**임을 README에 명시한다.

## 11. 검증 방법

- 담당 직원 3~5명에게 “처음 보는 상태에서 이미지 3장을 올리고 4대 화면에 순환 송출” 과제를 준다.
- 측정: 완료 시간, 막힌 지점, 잘못 누른 버튼, 도움말 사용 횟수, 주관적 난이도.
- 목표: 10분 이내 완료, 치명적 오해 0건, “다음에 무엇을 해야 하는지 모르겠다” 응답 20% 이하.
- 결과를 `docs/research/usability-test.md`에 기록하고 화면을 수정한다.
