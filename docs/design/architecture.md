# 범용 이미지 송출 시스템 아키텍처

작성 2026-11-24 / 모니터 수·배치·해상도·방향 비고정 요구 반영

## 1. 목표

특정 모니터 수나 배치를 코드에 고정하지 않고, 설치 장소마다 관리자가 모니터 구성과 재생 방식을 설정해 운영할 수 있는 이미지 송출 시스템을 만든다.

- 모니터 1대부터 다수까지 지원
- 장소별 독립 모니터 그룹
- 가로·세로·격자·사용자 지정 배치
- 모니터별 해상도·방향
- 연결된 모니터 자동 인식과 수동 등록
- 이미지 규격 검사와 화면 비율 유지
- 개별·순환·동시·통합 화면 재생
- 이미지 수량과 모니터 수량이 달라도 정상 동작
- 모니터 추가·연결 해제 대응
- 실제 송출 전 가상 모니터 미리보기
- 장비 지원 기능에 따른 송출 모듈 선택

## 2. 설계 원칙

1. **모니터 수를 코드에 상수로 두지 않는다.** 모든 계산은 설정 배열과 식별자에 기반한다.
2. **관리·엔진·송출을 분리한다.** 관리 화면은 설정과 콘텐츠를 관리하고, 엔진은 “지금 각 화면에 무엇을 그릴지”만 계산하며, 송출 모듈은 그 결과를 실제 화면에 그린다.
3. **엔진은 순수 로직으로 만든다.** DOM·파일 시스템·OS API를 직접 쓰지 않고, 같은 코드를 브라우저 미리보기·서버 테스트·네이티브 플레이어에서 재사용한다.
4. **표준 HTTP/JSON과 브라우저 API를 쓴다.** 특정 하드웨어·OS·클라우드에 종속되지 않는다.
5. **이미지 송출의 안정성과 사용 편의성을 우선한다.** 동영상·소셜·분석·멀티테넌시는 MVP 이후로 미룬다.
6. **실패를 전제로 설계한다.** 서버 단절, 모니터 추가·제거, 재부팅, 해상도 변경, 이미지 규격 불일치를 정상 흐름으로 다룬다.

## 3. 계층 구조

```text
┌──────────────────────────────────────────────┐
│ 관리 프로그램 (Web Admin, 한국어)            │
│ 사이트·그룹·모니터·배치·콘텐츠·재생목록·미리보기 │
└──────────────────────┬───────────────────────┘
                       │ 설정·게시
┌──────────────────────▼───────────────────────┐
│ 재생 엔진 (Pure JS/TS, DOM/OS 비의존)        │
│ 시간축·이미지 선택·배치 매핑·동기화·검증       │
└──────────────────────┬───────────────────────┘
                       │ RenderPlan (JSON)
┌──────────────────────▼───────────────────────┐
│ 송출 모듈 (Output Module)                    │
│ 웹 브라우저 / WPF·Electron / Pi 키오스크 ...   │
└──────────────────────────────────────────────┘
```

### 모듈 경계

| 모듈 | 책임 | 하지 않는 일 |
|---|---|---|
| 관리 프로그램 | 사이트·모니터·배치·콘텐츠·재생목록·권한·게시·미리보기 | 화면에 직접 그리지 않음 |
| 재생 엔진 | 현재 시각의 이미지·자르기·회전·전환 계획 계산 | 네트워크·파일·OS 접근 |
| 송출 모듈 | RenderPlan을 실제 화면에 그림, 하트비트·명령 처리 | 재생 순서를 자체 판단하지 않음 |
| 전송 계층 | manifest·asset·시각·상태 API | 화면 구성 규칙을 갖지 않음 |

## 4. 데이터 모델

```text
Site 1─* DisplayGroup 1─* Display
  │                         │
  │                         └─ LayoutSlot (x, y, w, h, rotation)
  │
  ├─ Layout 1─* DisplayGroup
  ├─ Playlist 1─* PlaylistItem *─ ImageAsset
  └─ Publication (version, epoch, snapshot)
```

### Site

- `id`, `name`, `timezone`, `notes`.
- 예: “국립부산국악원 A 인포메이션센터”, “국립부산국악원 B 인포메이션센터”.
- 사이트마다 독립 재생목록·모니터 그룹·게시 버전을 가진다.

### DisplayGroup

- `id`, `siteId`, `name`, `layoutId`, `playbackMode`, `playlistId`, `epoch`, `settings`.
- 한 사이트에 여러 그룹을 둘 수 있다. 예: 로비 그룹(4대, 순환 동기화), 안내 그룹(2대, 개별 재생).

### Display

- `id`, `groupId`, `name`, `hardwareId`, `resolution`, `orientation`, `rotation`, `capabilities`, `status`, `lastSeen`, `pairingState`.
- `id`는 영구 식별자다. 배열 순서나 모니터 번호를 식별자로 쓰지 않는다.
- `hardwareId`는 브라우저 localStorage 또는 네이티브 장비 ID에서 생성한다. 브라우저 저장소가 초기화되면 수동 재등록할 수 있다.

### Layout

- `id`, `name`, `type`(`single`/`row`/`column`/`grid`/`custom`), `canvasWidth`, `canvasHeight`, `slots[]`, `bezel`, `safeArea`.
- `slots[]`는 `displayId`가 아니라 배치 슬롯이다. 모니터를 추가·제거하면 슬롯에 다시 매핑한다.
- 좌표는 정규화(0~1) 또는 mm 단위를 함께 저장한다. 미리보기와 실제 송출의 비율을 맞추기 위해서다.

### Playlist

- `id`, `name`, `items[]`.
- `PlaylistItem`: `imageId`, `durationMs`, `fitMode`(`contain`/`cover`/`stretch`), `transitionMs`, `enabled`.

### ImageAsset

- `id`, `filename`, `width`, `height`, `aspectRatio`, `mime`, `size`, `checksum`, `thumbnailUrl`, `displayUrl`, `createdAt`.
- 업로드 시 규격을 검사하고, 필요하면 화면용 변환본·썸네일을 만든다.

### Publication

- `version`, `siteId`, `epoch`, `snapshot`(그룹·모니터·배치·재생목록의 불변 스냅샷), `publishedAt`, `publishedBy`.
- 플레이어는 버전이 바뀌면 새 스냅샷을 받고, 다음 전환 경계에서 반영한다.

## 5. 재생 모드

한 사이트 안에서도 그룹별로 다른 모드를 쓸 수 있다.

### 5.1 개별 재생 (individual)

- 모니터마다 독립 재생목록과 시간축을 가진다.
- 다른 화면과 전환 시각을 맞출 필요가 없을 때 쓴다.
- 예: A 모니터는 공연 포스터, B 모니터는 안내 이미지.

### 5.2 순환 동기화 (synchronized-cycle)

- 그룹의 모든 모니터가 같은 epoch와 같은 전체 주기를 공유한다.
- 각 모니터는 `startIndex`와 `step`을 가진다.
- `slot = floor((now - epoch) / dwell)`; `imageIndex = (startIndex + step × slot) mod imageCount`.
- 예: 4대, 이미지 A·B·C·D, step -1이면 1주기 A·B·C·D, 2주기 D·A·B·C.
- 이미지 수와 모니터 수가 달라도 아래 6절 규칙으로 동작한다.

### 5.3 동시 재생 (mirror)

- 그룹의 모든 모니터가 같은 이미지·같은 시각을 보여준다.
- `startIndex`와 `step`을 모두 같게 두면 순환 동기화가 동시 재생이 된다.
- 모니터별 해상도·방향이 다르면 각자 `contain`/`cover`로 맞춘다.

### 5.4 통합 화면 (canvas)

- 모니터들을 하나의 가상 캔버스로 묶고, 큰 이미지 한 장을 나눠 보여준다.
- 각 모니터는 캔버스에서 자기 영역만큼 자른 이미지를 표시한다.
- 베젤 보정, 가로/세로 혼합, 격자/사용자 지정 배치를 지원한다.
- 이미지 수는 모니터 수와 무관하다. 한 장이면 고정, 여러 장이면 캔버스 단위로 순환한다.

### 5.5 혼합 (mixed)

- 사이트 안의 그룹별로 모드를 다르게 둔다.
- 예: 로비 4대는 통합 화면, 옆 안내 1대는 개별 재생.

## 6. 이미지 수와 모니터 수가 다른 경우

`N`장의 이미지, `M`대의 모니터라고 하자.

| 조건 | 동작 |
|---|---|
| `N = 0` | 모든 화면에 “콘텐츠 없음” 플레이스홀더. 관리 화면에 경고 |
| `N = 1` | 모든 화면에 같은 이미지 유지(또는 개별 모드에서 1대만) |
| `1 < N < M` | 이미지를 라운드로빈으로 배정하고, 부족하면 반복. `startIndex`로 중복 위치를 분산 |
| `N = M` | 1주기에 1:1 배정. 순환 시 함께 이동 |
| `N > M` | 각 화면이 전체 이미지를 시간에 따라 순환. `step`과 오프셋으로 같은 이미지가 동시에 겹치지 않게 분산 |
| `M`이 나중에 증가 | 새 슬롯에 다음 이미지/오프셋을 배정. 기존 화면의 재생 위치는 유지 |
| `M`이 감소 | 남은 화면의 슬롯을 재배치. 배열 인덱스가 아니라 displayId로 추적 |

### 순환 패턴 미리보기

- 관리 화면에서 `LCM(N, M)` 주기까지의 표를 보여준다. 예: N=3, M=4 → 12슬롯.
- 어떤 이미지가 어떤 모니터에 언제 겹치는지, 빈 슬롯이 없는지 확인한다.
- N과 M이 서로소가 아니면 일부 조합이 반복되지 않을 수 있다. 이는 오류가 아니며, 운영자가 패턴을 보고 이미지 수를 조정할 수 있게 안내한다.

## 7. 배치와 좌표계

| 유형 | 설명 |
|---|---|
| single | 1대 전체 화면 |
| row | 가로 N대, 동일/가변 폭 |
| column | 세로 N대 |
| grid | rows × columns. 셀 크기·간격·베젤 설정 |
| custom | 관리자가 캔버스에 모니터를 자유 배치. L자, 계단, 혼합 방향 |

- 각 모니터는 `x, y, w, h`(정규화)와 실제 해상도·방향·회전을 가진다.
- `row/column/grid`는 모니터 수와 간격으로 좌표를 자동 생성한다. `custom`은 드래그·리사이즈로 저장한다.
- 겹침·빈 공간·화면 밖 배치는 저장 전에 검사하고 경고한다.
- 베젤은 미리보기에서 회색 띠로 표시하고, 통합 화면에서는 베젤 보정값을 적용한다.

## 8. 해상도·방향·이미지 규격

- 모니터별 `width × height`, `orientation`(landscape/portrait), `rotation`(0/90/180/270)을 저장한다.
- 이미지 업로드 시 실제 픽셀 크기와 EXIF 방향을 읽는다.
- 모니터 비율과 이미지 비율 차이가 10%를 넘으면 경고하고, `contain`/`cover`/`stretch` 중 선택하게 한다. 기본은 `contain`(잘림 없음).
- 세로 모니터에는 세로 템플릿을 권장하고, 가로 이미지를 억지로 늘리지 않는다.
- 지원 형식: JPEG, PNG, WebP(정적). GIF/동영상은 MVP 이후.
- 업로드 상한·해상도 상한·용량 상한을 설정하고, 썸네일과 화면용 변환본을 만든다.

## 9. 모니터 자동 인식·수동 등록

### 자동 인식

1. 플레이어가 `?site=<siteKey>`로 접속한다.
2. localStorage의 `hardwareId`와 화면 정보(해상도·방향·브라우저·다중 창 지원)를 서버에 등록한다.
3. 서버는 `pending` 상태로 만들고 관리자에게 알린다.
4. 관리자가 승인하고 그룹·슬롯을 배정하면 게시된다.

### 수동 등록

- 관리자가 모니터를 미리 만들고 6자리 코드 또는 등록 URL을 발급한다.
- 플레이어에서 코드를 입력하거나 URL을 열면 연결된다.
- 브라우저 저장소가 지워지거나 하드웨어 ID가 바뀌어도 재등록할 수 있다.

### 추가·해제

- 현재 MVP 구현은 15초 heartbeat와 45초 online 판정 창을 사용한다(`HEARTBEAT_MS=15000`, `HEARTBEAT_ONLINE_SECONDS=45`). 운영 화면의 `status`는 `last_seen` 기준이며, heartbeat 생존 상태는 별도 `health=stale`로 구분한다.
- 모니터 제거 시 그룹 레이아웃을 자동 재배치하거나, 운영자가 빈 슬롯을 유지할지 선택한다.
- 모니터 추가 시 빈 슬롯 → 자동 배정, 없으면 새 행/열 또는 사용자 지정 배치를 제안한다.
- 모든 상태 변화는 감사 로그에 남긴다.

## 10. 가상 모니터 미리보기

- 관리 화면에 사이트의 가상 캔버스를 그리고, 각 모니터에 현재 이미지·다음 이미지·전환 시각을 표시한다.
- 재생/일시정지/시간 이동(스크럽)을 지원한다.
- 모드 전환(개별/순환/동시/통합)을 미리 보여준다.
- 경고: 이미지 없음, 비율 불일치, 모니터 겹침, 빈 슬롯, 오프라인 모니터, 이미지 수 부족.
- 미리보기와 실제 송출은 **같은 엔진**을 사용한다. 미리보기용 별도 로직을 만들지 않는다.

## 11. 송출 모듈 인터페이스

```ts
interface OutputModule {
  id: string;
  capabilities(): OutputCapabilities;
  register(siteKey: string, pairingCode?: string): Promise<DisplayRegistration>;
  fetchManifest(displayId: string): Promise<Manifest>;
  render(plan: RenderPlan): void;
  heartbeat(status: DisplayStatus): Promise<void>;
  onCommand(command: Command): void;
}
```

### RenderPlan 예

```json
{
  "displayId": "disp-a1",
  "at": "2026-11-24T09:00:05+09:00",
  "imageId": "poster-b",
  "sourceRect": { "x": 0, "y": 0, "w": 1920, "h": 1080 },
  "destinationRect": { "x": 0, "y": 0, "w": 1080, "h": 1920 },
  "rotation": 90,
  "fit": "contain",
  "opacity": 1,
  "transitionMs": 300,
  "nextChangeAt": "2026-11-24T09:00:10+09:00"
}
```

- 웹 플레이어: `destinationRect`에 맞춰 DOM/Canvas로 그림.
- WPF/Electron: 같은 JSON을 받아 창·이미지 컨트롤에 그림.
- Pi 키오스크: Chromium 전체 화면으로 웹 플레이어 실행.
- Android/Tizen/webOS: 향후 어댑터 추가. 엔진은 그대로 재사용.

## 12. 장비별 송출 방식 선택

플레이어가 보고하는 capability를 기준으로 권장 모듈을 고른다.

| capability | 권장 |
|---|---|
| 브라우저 1개, 화면 1대 | 웹 플레이어(키오스크) |
| 브라우저 1개, 화면 여러 대, 다중 창 지원 | 네이티브 다중 창(WPF/Electron) |
| 브라우저 1개, 화면 여러 대, 다중 창 미지원 | 화면별 브라우저 창 또는 PC 분리 |
| 구형 Windows, 브라우저 없음 | WPF(.NET Framework 4.8) |
| Raspberry Pi/Linux | Chromium 키오스크 웹 플레이어 |
| 스마트 TV | 내장 브라우저/제조사 플레이어. 키오스크·자동 실행 확인 |

관리자가 자동 권장을 덮어쓸 수 있고, 선택한 모듈과 이유를 화면에 남긴다.

## 13. 배포 형태

### A. 모니터마다 PC

```text
[서버 PC/NAS] ── LAN ── [플레이어 PC 1] ─ 모니터 1
                    ├── [플레이어 PC 2] ─ 모니터 2
                    └── [플레이어 PC N] ─ 모니터 N
```

- 각 PC는 브라우저 키오스크. 서버가 manifest·이미지·시각을 제공.
- 가장 호환성이 좋고, 기존 PC를 그대로 쓰기 쉽다.

### B. 한 PC에 여러 모니터

```text
[서버 PC/NAS] ── LAN ── [플레이어 PC] ─┬─ 모니터 1
                                      ├─ 모니터 2
                                      └─ 모니터 N
```

- 네이티브 다중 창 플레이어가 모니터마다 창을 띄운다.
- 한 타이머로 전환하므로 네트워크 시계 오차가 없다.

### C. 혼합

- A센터는 한 PC + 4창, B센터는 PC 2대 + 브라우저. 같은 서버·같은 엔진을 쓴다.

## 14. 보안·운영

- 원내 LAN 전용. 외부 클라우드·CDN·유료 API 의존 없음.
- 관리자 인증, 세션 만료, 최소 권한, 감사 로그.
- 업로드 확장자·MIME·픽셀·용량 검증, 경로 조작 방지, 실행 파일 업로드 차단.
- 서버는 비관리자 계정으로 실행. 방화벽은 필요한 포트만.
- DB·이미지·설정 백업, 복구 리허설.
- 플레이어 자동 시작·watchdog·절전 해제·NTP.
- 서명·반입·보안성 검토 절차는 기관 정책에 맞춘다.

## 16. 완료 기준

- 모니터 1대, 3대, 8대에서 같은 코드로 동작한다.
- 이미지 0장, 1장, 3장, 10장에서 오류 없이 동작한다.
- 모니터를 추가·제거해도 재생이 멈추지 않고 배치가 갱신된다.
- 미리보기와 실제 송출이 같은 이미지·자르기·회전을 보여준다.
- 유선 LAN에서 이미지 전환 오차 200ms 이내.
- 서버 10분 단절·재부팅 후 자동 복구.
- 일반 직원이 10분 안에 새 사이트를 만들고 첫 이미지를 게시할 수 있다.
- 새 송출 모듈을 추가해도 엔진·관리 화면을 고치지 않는다.
