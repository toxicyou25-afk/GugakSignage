# 오픈소스 운영 원칙

## 공개 범위

- 이 저장소의 자체 코드와 문서는 **Apache License 2.0**으로 공개합니다.
- 연구 보고서에 인용된 상용 제품의 이름·화면·로고·아이콘은 각 권리자의 자산이며, 이 프로젝트의 라이선스 대상이 아닙니다.
- 실제 서비스 화면 캡처는 조사 목적의 `artifacts/`에만 두고 저장소·배포물에 넣지 않습니다.
- 개인정보, 내부 연락처, 계약 정보, 비밀번호, API 키는 공개하지 않습니다.

## 왜 Apache-2.0인가

- 공공기관과 민간 모두 추가 비용 없이 사용·수정·재배포할 수 있습니다.
- 특허 허여 조항이 있어, 기여자가 보유한 특허를 이유로 사용자를 제한하는 위험을 줄입니다.
- 기여·변경·고지 방식이 명확해 장기 운영과 외부 기여에 적합합니다.
- MIT보다 문서가 길지만, 공공 프로젝트에서 검토하기 쉬운 표준 라이선스입니다.

## 기여와 고지

- 기여물은 Apache-2.0으로 제공됩니다. 자세한 내용은 [CONTRIBUTING.md](../CONTRIBUTING.md)를 참고하세요.
- 새 소스 파일에는 가능하면 `SPDX-License-Identifier: Apache-2.0`을 넣습니다.
- 제3자 코드·아이콘·폰트·이미지를 추가하면 [licenses.md](research/licenses.md)와 `NOTICE`에 출처·라이선스·고지 문구를 기록합니다.
- GPL/AGPL 코드를 가져오려면 먼저 Issue에서 논의합니다.

## 재사용하는 기관·개발자를 위한 안내

1. `LICENSE`와 `NOTICE`를 함께 보관합니다.
2. 수정한 파일에 변경 사실을 표시합니다.
3. 제3자 자산의 고지문을 삭제하지 않습니다.
4. 국립부산국악원의 공식 로고·표장을 무단으로 사용하지 않습니다.
5. 운영 환경의 이미지·설정·로그에 개인정보가 들어가지 않게 합니다.

## 공개 전 점검

- `git grep`으로 로컬 경로·이메일·전화번호·토큰·비밀번호를 확인합니다.
- `artifacts/`와 `node_modules/`가 커밋되지 않았는지 확인합니다.
- 상용 제품 화면·로고·아이콘이 저장소에 없는지 확인합니다.
- `LICENSE`, `NOTICE`, `CONTRIBUTING.md`, `SECURITY.md`가 있는지 확인합니다.
- GitHub 저장소가 `public`이고 기본 브랜치가 `main`인지 확인합니다.


## 열린안내판 벤치마킹 원칙
