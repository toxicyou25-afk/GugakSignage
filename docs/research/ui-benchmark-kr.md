### 1.1 핵심 발견 5

1. **제품의 뼈대는 비슷하지만, 첫 화면의 결론은 다르다.** 삼성·LG·위캐스트는 장소·기기·콘텐츠·스케줄·상태를 한 제품에 묶는다. 그러나 초보자에게 필요한 것은 기능 목록이 아니라 “지금 무엇을 하면 되는가”다. Y_BOARD의 “사용 빈도” 표시와 LG의 요약 카드는 참고하되, 태그·채널·역할은 첫 흐름에서 숨긴다.
2. **미리보기·시뮬레이션이 가장 큰 공백이다.** LG는 편집·스케줄 썸네일과 게시 후 화면 캡처를 제공하지만, 공개 자료에서 실제 송출 전 다중 모니터 시간축 시뮬레이션은 확인되지 않았다. 삼성·위캐스트도 마찬가지다. 같은 엔진으로 가상 모니터·시간 이동·경고를 보여주는 것이 우리의 핵심 차별점이다.
3. **상태는 “색”이 아니라 “다음 행동”으로 설계해야 한다.** LG의 기기 상태·오류 카드, 위캐스트의 정상/대기/오류/다운로드 중, LG Control+의 이슈·제어·전원 이력이 좋은 참고다. 홈에는 “주의 필요” 큐를 두고, 각 오류에 복구 버튼과 원인·다음 행동을 붙인다.
4. **한국어 접근성 기준은 이미 구체적이다.** KRDS는 17px Pretendard GOV, 150% 이상 줄 간격, 4.5:1 본문 대비, 3:1 UI 대비, 보이는 포커스, 44px 터치 영역, 키보드·오류 정정·표 마크업을 요구한다. 여기에 한글 줄바꿈(keep-all + 긴 토큰 예외)과 고대비 모드를 더한다.
5. **공공기관 통제는 제품별 편차가 크다.** 위캐스트는 배포 승인을, LG는 역할·게시 이력을 제공하지만, Y_BOARD 매뉴얼에서는 승인·감사 로그를 확인하지 못했다. 우리는 초안→검토→승인→송출→감사 로그→복구를 MVP에 넣고, 외부 클라우드·CDN·분석 도구 없이 자체 호스팅한다.

### 2.2 확인된 흐름

QM43C 매뉴얼은 서버 관리 화면이 아니라 **디스플레이 내장 MagicInfo 플레이어**의 화면이다. 내부 메모리, 네트워크 채널, 네트워크 파일, 내 템플릿, 재생목록, 화면 분할, 예약 재생 등을 다룬다. 이 매뉴얼에서 다음 제약이 확인된다.

- 세로 방향은 콘텐츠 해상도가 3840×2160을 넘으면 지원하지 않는다.
- 3840×2160을 넘는 비디오는 전체 화면 크기만 지원한다.
- 내부/USB 메모리에 사진이 한 장뿐이면 슬라이드 쇼를 재생할 수 없다.
- 폴더 이름이 너무 길면 선택할 수 없다.

### 2.3 한국어 강점

- 제품 페이지와 플레이어 매뉴얼이 한국어로 제공된다.
- 매뉴얼이 기기 메뉴 위치와 리모컨 버튼을 그림으로 설명해, 현장 직원이 플레이어 자체를 다룰 때는 도움이 된다.
- “네트워크 채널”, “내 템플릿”, “재생목록”처럼 플레이어 메뉴 이름을 한국어로 확인할 수 있다.

### 2.4 초보자가 막히는 지점

- MagicINFO 9의 가치 제안이 콘텐츠 제작, 기기 관리, 데이터 분석, 판매 연동, 보안 인증까지 넓다. 첫 화면에서 “무엇부터 해야 하는지”를 알려주는 공개 온보딩 자료가 없다.
- 서버 관리자 매뉴얼과 실제 관리 화면이 파트너 전용이라, 일반 행정직원이 사전에 학습할 수 있는 자료가 부족하다.
- 디바이스, 콘텐츠, 플레이리스트, PoP, Datalink 같은 용어가 제품 설명에 먼저 등장한다.
- 플레이어 매뉴얼과 서버 관리 매뉴얼의 대상이 다르다. 현장 직원이 “모니터 화면에서 하는 일”과 “관리 PC에서 하는 일”을 구분하기 어렵다.
- 삼성 비즈니스 사이트는 MagicINFO와 별도로 클라우드형 VXT CMS를 안내한다. 온프레미스 MagicINFO의 지원 정책과 VXT 전환 계획은 공식 채널로 확인해야 한다. VXT는 클라우드형이므로 외부 클라우드 미의존 요구와 맞지 않을 수 있다.
- 파트너 채널 웨비나(2026년)는 온프레미스 MagicINFO 서비스 종료를 언급하지만, 삼성 공식 공지로 확인하지 못했다. 장기 운영 제품을 고를 때는 반드시 삼성 공식 채널로 지원 기간을 확인해야 한다.

### 2.5 참고할 것 / 피할 것

**참고**

- 콘텐츠·기기·상태·성과를 한 제품군으로 묶는 정보 구조.
- 기기 상태, 펌웨어, 원격 설정, 재생 기록을 별도 메뉴로 두는 방식.
- PoP(재생 증명)처럼 “무엇이 실제로 재생되었는가”를 운영자가 확인하는 개념. 우리 시스템에서는 MVP 이후 검토하되, 게시 이력과 화면 캡처로 단순화할 수 있다.
- 플레이어 매뉴얼의 “지원 해상도·파일 형식·세로 방향 제한”을 업로드 검사 문구에 반영하는 방식.

**피할 것**

- 기능 목록을 첫 화면에 모두 노출하는 엔터프라이즈형 정보 구조.
- 파트너 전용 문서에만 의존하는 운영. 우리 시스템은 관리자 매뉴얼과 화면 도움말을 제품 안에 포함해야 한다.
- 검증되지 않은 “서비스 종료” 정보를 사실처럼 취급하는 것. 도입 검토 시 공식 지원 정책을 확인한다.
- 삼성의 마케팅 이미지·아이콘·로고·화면을 복제하는 것.

### 3.3 한국어 강점

- LG의 글로벌 제품 설명은 영어이며, 공개된 한국어 SuperSign 전용 페이지는 확인하지 못했다. 한국어 UI 자체가 없다고 단정할 수는 없지만, **공개 자료만으로는 한국어 용어·문구·도움말을 검증할 수 없다**.
- 한국 LG 사업자몰은 사이니지 하드웨어를 한국어로 판매하지만, SuperSign CMS의 관리자 화면·매뉴얼은 제공하지 않는다.
- 따라서 한국어 초보자 관점의 벤치마크로는 LG보다 Y_BOARD·위캐스트·시스메이트 사례가 더 직접적이다.

### 3.4 초보자가 막히는 지점

- 디바이스, 콘텐츠, 플레이리스트, 스케줄, 태그, 채널, 비디오월, 역할이 한 제품 안에 함께 등장한다. 처음 쓰는 직원에게는 결정할 것이 많다.
- CMS와 Cloud와 Control+가 서로 다른 제품군이다. 콘텐츠 관리, 클라우드, 원격 제어의 경계를 이해해야 한다.
- 태그 기반 배포는 유연하지만, “어떤 태그가 어떤 화면에 붙었는지”를 먼저 이해해야 한다. 장소·모니터가 2~9대인 우리 환경에는 과한 추상화다.
- 역할·권한·게시 이력은 훌륭하지만, 공개 자료만으로 승인 단계의 실제 UI와 알림을 알 수 없다.
- 한국어 문서 부재로, 일반 행정직원이 스스로 학습하기 어렵다.

### 3.5 참고할 것 / 피할 것

**참고**

- 대시보드의 “기기 상태 + 오류 + 콘텐츠 수 + 저장공간” 카드 구성. 우리 홈은 여기에 “다음 할 일”과 “게시되지 않은 초안”을 추가한다.
- Map View/List View 전환. 우리는 “배치 보기/목록 보기”로 단순화한다.
- 스케줄 표의 기기 행 × 시간 열, 플레이리스트 표의 순서·표시 시간·재생 열.
- 게시 이력, 재생 이력, 기기 이슈 이력을 각각 분리하는 정보 구조.
- 역할 분리와 다중 관리자. 단, 첫 화면에서는 숨기고 “고급 설정”으로 내린다.
- Cloud의 화면 캡처 검증은 “게시 후 실제 화면 확인”이라는 강력한 피드백이다. 우리는 MVP에서 “게시 후 상태 확인”으로 단순화하고, 캡처는 2차로 검토한다.

**피할 것**

- 태그·채널·역할을 첫 사용 흐름에 노출하는 것.
- 비디오월·다채널·외부 데이터 연동을 기본값으로 두는 것. 우리 요구는 정적 이미지 송출이다.
- 브로셔의 예시 화면을 실제 제품 화면처럼 인용하는 것.
- 한국어 문서 없이 “한국어 UI가 잘 되어 있다”고 주장하는 것.

### 5.4 초보자가 막히는 지점

- 매뉴얼상 장치 추가는 **납품사 권한**이다. 일반 직원이 스스로 화면을 등록할 수 없다.
- 관리자 프로그램은 Windows 설치형이며, 동시 접속이 불가능하다. 여러 직원이 동시에 운영하기 어렵다.
- 장치 목록·설정·재생목록·영역 분할이 한 화면에 밀도 높게 배치되어 있다. 처음 보는 직원에게는 “어디를 먼저 눌러야 하는지”가 불명확하다.
- 화면 분할은 15개 프리셋과 4개 영역 중심이다. 모니터 4대를 자유 배치하는 우리 요구에는 부족하다.
- 예약 시점에 기존 재생목록이 자동으로 사라진다. 미리보기·확인 없이 송출이 바뀌는 위험이 있다.
- 승인·감사 로그·게시 이력이 매뉴얼 범위에서 확인되지 않는다. 공공기관 운영에 필요한 통제가 약하다.
- 매뉴얼은 Windows 프로그램인데 현재 웹 매니저를 홍보한다. 문서와 제품의 불일치가 학습 부담을 만든다.

### 5.5 참고할 것 / 피할 것

**참고**

- 화면 캡처에 번호·화살표·주의 문구를 붙인 한국어 매뉴얼. 우리 도움말 패널과 첫 사용 안내에 같은 방식을 쓸 수 있다.
- “설정 복사”로 비슷한 모니터 여러 대를 한 번에 설정하는 기능. 우리는 “다른 모니터에 설정 적용”으로 제공한다.
- 오프라인 기기를 위한 USB 설정 저장, 마지막 설정 유지.
- “사용 빈도” 라벨로 고급 기능을 접어 두는 정보 구조.
- 전송 중 이탈 금지 같은 구체적 주의 문구.

**피할 것**

- 장치 추가를 공급업체만 할 수 있게 하는 것. 우리는 자동 발견 + 승인, 코드 등록, 링크 등록을 제공한다.
- 단일 관리자 동시 접속 제한.
- 한 화면에 모든 설정을 넣는 고밀도 UI.
- 예약 시점에 기존 재생목록을 무조건 교체하는 방식.
- 4개 영역·15개 프리셋만으로 다중 모니터 배치를 해결하려는 것.

- “천정형”, “안내데스크”, “매표요금안내”처럼 기관 현장에서 쓰는 용어를 그대로 쓴다.
- 설치 사진과 현장 설명을 함께 제공해, 비전문가도 어떤 공간에 어떤 화면이 놓였는지 이해할 수 있다.

### 6.4 초보자가 막히는 지점

- 관리자 화면·매뉴얼·데모가 없어, 직원이 직접 운영하는 흐름을 학습할 수 없다.
- 공급업체가 설치·설정·유지보수를 주도하는 구축형 모델이라, 내부 직원의 셀프서비스 수준을 알 수 없다.
- 9대를 어떻게 묶었는지, 동기화·재생 모드·미리보기·승인·감사 기능이 있는지 확인할 수 없다.
- 2021년 사례라 현재 제품 UI와 같다고 볼 수 없다.

### 6.5 의미

- 우리 기관에도 이미 9대 규모의 천정형 디스플레이가 설치되어 있었고, 공연 정보·요금·홍보 영상이 핵심 콘텐츠였다는 점은 화면 설계의 출발점으로 중요하다.
- 9대를 한 관리 PC에서 바꾸는 운영 방식은 “다중 모니터를 하나의 장소로 묶는” 우리 요구와 맞닿아 있다.
- 다만 동기화 방식, 재생 모드, 미리보기, 승인·감사 기능은 공개 자료로 확인할 수 없다.
- 공급업체가 설치·운영을 주도하는 구축형 모델이라, 일반 직원이 매뉴얼 없이 쓰는 UI를 벤치마크하기에는 부족하다.

### 6.6 참고할 것 / 피할 것

**참고**

- 실제 콘텐츠 유형: 공연 정보, 매표 요금, 홍보 영상.
- 9대 천정형 디스플레이, 안내데스크 눈높이, 178도 시야각 같은 현장 조건.
- 관리자 PC에서 콘텐츠를 바꾸는 운영 개념.

**피할 것**

- 공급업체 의존 운영을 그대로 답습하는 것. 우리는 직원이 직접 운영할 수 있는 한국어 UI와 매뉴얼을 제공해야 한다.

피할 것: 미리보기를 이미지 썸네일로만 제공, 실제 송출과 다른 별도 로직, 자동 재생에 정지 버튼 없음.

### 9.6 상태·오류

피할 것: 빨간 점만 표시, 오류 코드만 표시, “관리자에게 문의”로 끝내기, 복구 버튼 없는 상태 화면.

## 10. 한국어 초보자 흐름 제안

벤치마크를 종합하면, 국내·외 제품의 공통 뼈대는 “장소 → 화면 → 콘텐츠 → 스케줄 → 송출 → 상태”다. 그러나 초보자에게 필요한 것은 이 뼈대를 그대로 보여주는 것이 아니라, **한 화면에 한 가지 결정**만 남기는 것이다.

### 10.1 첫 송출 6단계

| 단계 | 화면 | 사용자가 하는 일 | 시스템이 돕는 일 | 완료 조건 |
|---|---|---|---|---|
| 1 | 장소 만들기 | 이름, 운영 시간 입력 | 1대·가로·세로·격자 템플릿 제안 | 장소 저장 |
| 2 | 화면 등록 | 자동 발견 목록에서 승인, 또는 코드·링크 등록 | 해상도·방향·브라우저 표시, 테스트 이미지 | 모니터 1대 이상 연결 |
| 3 | 배치 정하기 | 템플릿 선택, 필요하면 드래그 | 겹침·빈 공간·화면 밖 경고, 키보드 미세 조정 | 배치 저장 |
| 4 | 이미지 올리기 | 끌어다 놓기 또는 파일 선택 | 형식·용량·해상도·비율 검사, 썸네일 | 이미지 1장 이상 통과 |
| 5 | 재생 정하기 | 모드 선택, 순서·시간·시작 위치 설정 | 이미지 수/모니터 수 패턴 미리보기, 자동 채우기 | 재생안 저장 |
| 6 | 미리보기·송출 | 가상 모니터로 재생, 게시 | 오류·오프라인·비율 경고, 게시 요약 | 게시 완료 |

- 각 단계는 “저장 후 나중에 이어서” 가능해야 한다.
- 1~3단계는 장소를 만들 때 한 번, 4~6단계는 이미지가 바뀔 때 반복한다.
- 상단에 “1/6” 단계 표시와 “다음: 이미지 올리기”를 항상 보여준다.
- “이전”은 데이터를 잃지 않고, “나가기”는 초안 저장을 확인한다.

### 10.2 빠른 교체 3단계

기존 장소에서 이미지 몇 장만 바꾸는 경우:

1. **이미지 올리기** — 기존 이미지 목록에 추가, 교체할 이미지 선택.
2. **순서 확인** — 기존 순서를 유지한 채 새 이미지 위치만 조정.
3. **미리보기·송출** — 실제 모니터 배치로 확인 후 게시.

홈의 장소 카드에 “이미지 바꾸기” 버튼을 두고, 이 3단계로 바로 진입한다.

### 10.3 용어

| 전문 용어 | 첫 화면 용어 | 괄호 병기 |
|---|---|---|
| 디바이스 | 모니터 | 디바이스 |
| 콘텐츠 | 이미지 | 콘텐츠 |
| 플레이리스트 | 이미지 순서 | 재생목록 |
| 스케줄 | 재생 시간표 | 스케줄 |
| 싱크 그룹 | 함께 묶인 화면 | 동기화 그룹 |
| 태그 | (첫 화면에서 숨김) | 태그 |
| 채널 | (첫 화면에서 숨김) | 채널 |
| PoP | 게시·재생 기록 | PoP |

- “송출”, “게시”, “저장”을 섞지 않는다. 최종 행동은 **송출**로 통일한다.
- “삭제”와 “송출 취소”를 구분한다. “삭제”는 파일·장소에만 쓴다.
- 버튼은 동사형으로 쓴다. “확인”보다 “이대로 송출”, “이미지 올리기”가 좋다.

### 10.4 고급 설정으로 내릴 것

- 태그, 채널, 역할·권한, IP·포트, 베젤 보정, 회전, 화면 캡처 주기, 외부 데이터 연동.
- 첫 사용 흐름에서는 “고급 설정” 링크로 숨기고, 현재 값과 기본값을 요약해 보여준다.
- 고급 설정을 바꾸면 “이 설정이 어떤 화면에 영향을 주는지”를 즉시 요약한다.

### 10.5 공공기관 승인·감사 흐름

국내 제품 중 위캐스트는 “배포 승인”을, LG는 역할·게시 이력을 제공한다. 반면 Y_BOARD 매뉴얼에서는 승인·감사 로그를 확인하지 못했다. 공공기관 운영에는 다음을 권장한다.

1. **초안** — 작성자가 저장. 아직 송출되지 않음.
2. **검토 요청** — 검토자에게 알림. 변경 요약(장소, 모니터 수, 이미지 수, 모드, 경고)을 함께 보낸다.
3. **승인·반려** — 승인자 이름, 시각, 의견을 기록. 반려 시 작성자에게 사유를 보낸다.
4. **송출** — 승인된 버전만 송출. 송출 요약과 버전 번호를 남긴다.
5. **긴급 송출** — 사유를 입력하고 즉시 송출. 사후 승인과 감사 로그를 남긴다.
6. **되돌리기** — 이전 버전으로 복구. 복구도 새 버전으로 기록한다.

감사 로그에 남길 항목:

- 시각(서버 기준, NTP 동기화), 사용자 ID, 역할, 작업(로그인·업로드·수정·삭제·승인·송출·복구·권한 변경), 대상(장소·모니터·이미지·재생안), 변경 전후 요약, 결과, IP(필요 시 마스킹).
- 로그는 추가 전용(append-only)으로 하고, 일반 관리자도 수정·삭제할 수 없게 한다.
- CSV 내려받기와 기간 필터를 제공한다.
- 보존 기간은 기관 기록물·개인정보 정책에 맞춘다.

개인정보 최소화:

- 관리자 계정의 이름·아이디·권한만 수집한다. 주민번호·연락처·생년월일은 받지 않는다.
- 이미지 EXIF(촬영 위치·기기 정보)를 업로드 시 제거한다.
- 관람객 분석·카메라·얼굴 인식은 MVP에서 제외한다.
- 접속 기록의 IP는 운영에 꼭 필요하지 않으면 마스킹하거나 짧게 보존한다.
- 외부 폰트·아이콘·분석 도구를 런타임에 불러오지 않는다. 모두 자체 호스팅한다.
