# KRDS 요약과 관리자 UI 실무 체크리스트

- 작성·확인일: 2026-11-24 (KST)
- 대상: 대한민국 범정부 디지털 정부서비스 디자인 시스템(KRDS)
- 용도: 국립부산국악원 디지털 사이니지 관리자 화면의 스타일·컴포넌트·접근성·문구 기준
- 관련 문서: [국내 UI·UX 벤치마크](ui-benchmark-kr.md), [라이선스·출처](licenses.md)

## 0. 확인 범위와 표기

이 문서는 KRDS 공식 누리집의 공개 페이지와 공개된 HTML 컴포넌트 킷을 직접 확인해 정리했다. 모든 URL의 확인일은 2026-11-24(KST)이다.

- **확인**: KRDS 공식 페이지에 명시된 내용.
- **적용 제안**: KRDS 원문을 우리 관리자 화면에 맞게 해석한 내용. KRDS가 직접 요구한 것이 아님을 구분한다.
- **확인 불가**: 공개 페이지에서 찾지 못한 내용. 추정하지 않는다.

KRDS는 정부 웹·앱의 일관성과 포용성을 위한 디자인 시스템이다. 우리 제품은 KRDS를 참고하되, KRDS 구성 요소를 그대로 복제했다고 주장하지 않는다. 화면의 브랜드는 국립부산국악원의 내부 관리 도구로 한다.

## 1. KRDS가 제공하는 것

공식 소개 페이지는 KRDS를 “디자이너, 개발자, 정부 관계자 등 팀의 모든 구성원을 위한” 원칙·지침·코드로 설명한다.

- 디자인 원칙
- 디지털 포용
- 스타일(색상, 타이포그래피, 형태, 레이아웃, 아이콘, 엘리베이션, 선명한 화면 모드, 디자인 토큰)
- 컴포넌트 43종
- 기본 패턴 11종
- 서비스 패턴 5종

출처:

- [KRDS 시작하기](https://www.krds.go.kr/html/site/outline/outline_01.html)
- [디자이너·리소스 안내](https://www.krds.go.kr/html/site/outline/outline_02.html)
- [컴포넌트 소개](https://www.krds.go.kr/html/site/component/component_summary.html)
- [기본 패턴 소개](https://www.krds.go.kr/html/site/global/global_summary.html)
- [서비스 패턴 소개](https://www.krds.go.kr/html/site/service/service_summary.html)

KRDS의 접근성 기준은 다음을 함께 따른다.

- 한국형 웹 콘텐츠 접근성 지침 2.2(KWCAG 2.2)
- 전자정부 웹사이트 품질관리 지침(웹 접근성)
- 국제 표준 WCAG 2.1

출처: [KRDS 디지털 포용](https://www.krds.go.kr/html/site/utility/utility_04.html).

중요한 한계도 함께 밝힌다. KRDS는 “KRDS를 적용하는 것만으로 웹 접근성을 완벽하게 충족한다고 판단하기는 어렵다”고 설명한다. 화면 구현 후 KWCAG 검사와 실제 보조기술 테스트가 필요하다.

## 2. 디자인 원칙

KRDS는 7개 상위 원칙을 제시한다.

1. **사용자 중심의 서비스** — 조직이나 개발자가 아니라 사용자의 목표와 여정을 기준으로 결정한다.
2. **모든 사용자를 포용하는 서비스** — 장애인, 고령자, 어린이, 외국인을 포함해 서로 다른 능력·환경·상황의 사용자를 고려한다.
3. **공통된 경험 안에서 개별 특성을 고려한 서비스** — 정부 서비스로서 일관성을 유지하되, 기관·서비스의 특성에 맞게 조정한다.
4. **빠르고 간단한 서비스** — 필요한 의사 결정과 행동의 수를 줄인다.
5. **쉽게 이해하고 사용할 수 있는 서비스** — 친숙한 용어, 직관적 상호작용, 실수에서 돌아올 방법을 제공한다.
6. **사용자의 다양한 상황을 고려하는 서비스** — 숙련도, 빈도, 기기, 환경에 따라 선택할 수 있게 한다.
7. **신뢰할 수 있는 서비스** — 공식 서비스임을 알 수 있게 하고, 정보의 정확성·최신성을 유지한다.

출처: [KRDS 디자인 원칙](https://www.krds.go.kr/html/site/utility/utility_02.html).

### 우리 관리자 화면에 대한 해석

- 첫 사용자는 “이미지 3장을 올려 4대 모니터에 순환 송출”하는 목표를 10분 안에 달성해야 한다.
- 반복 사용자는 “오늘 상태 확인 → 이미지 교체 → 미리보기 → 송출”만 하면 된다.
- 숙련자는 태그·채널·권한·외부 연동 같은 고급 기능을 선택적으로 쓴다.
- 공식 내부 도구임을 헤더·푸터·버전·감사 로그로 분명히 한다.

## 3. 정보 구조

### 3.1 KRDS 누리집의 정보 구조

- 시작하기: KRDS 소개, 디자이너, 개발자, 정부 관계자, 리소스 다운로드
- 디자인 스타일: 소개, 색상, 타이포그래피, 형태, 레이아웃, 아이콘, 엘리베이션, 선명한 화면 모드, 디자인 토큰
- 컴포넌트: 아이덴티티, 탐색, 레이아웃·표현, 액션, 선택, 피드백, 도움, 입력, 설정, 콘텐츠
- 기본 패턴: 개인 식별 정보 입력, 도움, 동의, 목록 탐색, 사용자 피드백, 상세 정보 확인, 오류, 입력 폼, 첨부파일, 필터링·정렬, 확인
- 서비스 패턴: 방문, 검색, 로그인, 신청, 정책 정보 확인
- 소식·소통, 지원

이 구조는 “스타일 → 컴포넌트 → 패턴 → 서비스 여정”으로 올라가는 위계다. 우리 관리자 화면은 이 위계를 그대로 복제하지 않고, 업무 목적별 메뉴로 재구성한다.

### 3.2 우리 관리자 정보 구조

상단 메뉴는 5개로 제한한다.

- **홈** — 오늘의 송출 상태, 장소 카드, 다음 할 일, 최근 활동
- **장소** — 장소 목록, 장소 상세(배치·모니터·재생 설정·미리보기)
- **콘텐츠** — 이미지 보관함, 업로드·규격 검사, 이미지 상세
- **재생** — 재생 방식, 이미지 순서·표시 시간, 시작 위치, 게시 이력
- **미리보기** — 가상 모니터, 시간 이동·재생, 경고

설정(사용자·권한·서버·백업·감사 로그)은 오른쪽 위 사용자 메뉴에 둔다. 모니터 등록과 상태는 “장소” 안에서 처리해 메뉴를 늘리지 않는다.

사이드 메뉴는 최대 2단계로 제한한다. KRDS 사이드 메뉴 가이드는 3단계 이상을 한 번에 표시하면 인지·탐색이 어려워지므로, 하위 메뉴를 점진적으로 펼치거나 본문에 보조 탐색을 제공하라고 권한다. 현재 위치는 색만이 아니라 굵기·배경·aria-current로 표시한다.

출처: [KRDS 사이드 메뉴](https://www.krds.go.kr/html/site/component/component_03_04.html).

## 4. 스타일

### 4.1 타이포그래피

KRDS 표준형 스타일은 국문·영문 모두 **Pretendard GOV**를 기본 서체로 쓴다. Pretendard를 기반으로 공공기관의 접근성·가독성에 맞춰 만든 서체다.

핵심 수치:

- 본문 기본 크기: **17px**(Pretendard GOV 기준). KRDS는 다른 서체보다 작게 느껴져 17px을 기본으로 쓴다고 설명한다. 최소 16px 이상을 요구한다.
- 줄 간격: **150% 이상**, px가 아닌 em·% 같은 상대 단위.
- 글자 두께: regular 400, bold 700 중심. 이상적으로는 최대 4종, 권장은 400·500·700.
- 제목과 본문의 크기 차이: 1.25~1.5배.
- 본문 스케일: large 19px, medium 17px, small 15px, xsmall 13px.
- 제목 스케일: xlarge 40px, large 32px, medium 24px, small 19px, xsmall 17px, xxsmall 15px.
- 자간: 본문 0, 제목 0~1px. 한글에 음수 자간을 과하게 주지 않는다.
- 밑줄: 텍스트 링크에만 사용하고, 강조에는 색·굵기를 쓴다.
- 개발 시 rem을 사용해 브라우저 글자 크기 조절에 대응한다.

출처: [KRDS 타이포그래피](https://www.krds.go.kr/html/site/style/style_03.html).

**우리 적용 제안**

- 기본 17px, 줄 간격 1.6(프로젝트 UI-UX 기준). 표·보조 정보는 15px까지 허용하되 13px 미만은 쓰지 않는다.
- 긴 설명·도움말은 17px, 폼 레이블은 15~17px, 상태 배지는 15px 이상.
- 시간·용량·재생 시간은 tabular-nums로 숫자 폭을 맞춘다.
- 한글 줄바꿈은 word-break: keep-all, 긴 URL·파일명은 overflow-wrap: anywhere를 함께 쓴다.
- 표의 숫자는 오른쪽, 텍스트는 왼쪽 정렬한다.
- 200% 확대에서 잘리지 않도록 고정 높이를 피하고, 말줄임은 필요한 곳에만 쓴다.

### 4.2 색상과 명도 대비

KRDS 색상 체계의 핵심:

- Gray 0(White)~100(Black), 나머지 색상은 11단계.
- 매직넘버 40 = 3:1, 50 = 4.5:1, 70 = 7:1, 90 = 15:1.
- 기본 모드의 본문은 최소 4.5:1, 큰 텍스트·UI는 3:1.
- 선명한 화면 모드의 본문은 15:1, 제목·레이블·아이콘은 7:1, 시각 보조는 4.5:1.
- 60-30-10 비율: 배경·중립 60%, 보조 30%, 주요 기능 10%. 강조 색은 5%를 넘기지 않는다.
- 상태 색은 색만으로 전달하지 않고 아이콘·텍스트를 함께 쓴다.
- 적록색맹·청색맹을 고려해 적색-녹색 조합을 피하거나 명도 차를 준다.
- 입력 필드 테두리는 배경과 3:1 이상.
- 아이콘은 기본 모드 3:1, 선명한 화면 모드 7:1.

출처: [KRDS 색상](https://www.krds.go.kr/html/site/style/style_02.html), [KRDS 아이콘](https://www.krds.go.kr/html/site/style/style_06.html).

**우리 팔레트 제안**

프로젝트 UI-UX 초안의 짙은 남색, 한지 베이지, 청자색, 주홍을 유지하되 다음을 검증한다.

| 역할 | 색 예시 | 확인할 것 |
|---|---|---|
| 배경 | 한지 베이지 | 본문 텍스트와 4.5:1 이상 |
| 표면 | 밝은 베이지·흰색 | 카드 경계 3:1, 그림자만으로 구분하지 않기 |
| 주요 행동 | 짙은 남색 | 흰 글자 4.5:1 이상, 포커스 링 3:1 |
| 보조 | 청자색 | 링크·보조 버튼, 색만으로 구분하지 않기 |
| 경고·오류 | 주홍 | 아이콘+문구, 오류 텍스트 4.5:1 |
| 성공 | 차분한 녹색 | 정상 상태에만 제한적으로 사용 |

상태 배지는 “정상/대기/오류/오프라인” 텍스트를 항상 포함한다. 색은 보조 수단이다.

### 4.3 레이아웃과 반응형

KRDS 표준형 레이아웃:

- 8-point grid.
- 브레이크포인트: small 360px, medium 768px, large 1024px, xlarge 1280px.
- large 이상 12칼럼, medium 8칼럼, small 4칼럼.
- 최소 화면 여백: 24px(large·medium), 16px(small).
- 가터: 최소 16px, 권장 24px.
- 표준형 콘텐츠 최대 폭 1200px.
- 서브 페이지: header, 선택적 left menu, main contents, 선택적 right menu, footer.
- 폼은 가능한 한 한 열로 세로 정렬한다.
- 액션 버튼은 폼 오른쪽 아래, 제출 버튼이 가장 오른쪽.

출처: [KRDS 레이아웃](https://www.krds.go.kr/html/site/style/style_05.html), [KRDS 입력 폼](https://www.krds.go.kr/html/site/global/global_08.html).

**우리 적용 제안**

- 관리자 화면은 1920×1080을 기본, 1280×720을 최소 데스크톱으로 본다.
- 읽기·폼 영역은 최대 1200px, 배치 캔버스·스케줄 표·미리보기는 화면 전체 폭을 쓴다.
- 좌측 사이드 메뉴 240~280px, 우측 속성 패널 320~360px, 가운데 캔버스는 남는 폭.
- 1024px 미만에서는 사이드 메뉴를 접고, 우측 패널을 하단 시트로 전환한다.
- 768px 미만에서는 복잡한 배치 편집보다 상태 확인·빠른 교체·긴급 공지에 집중한다.
- 200% 확대에서 페이지 전체에 가로 스크롤이 생기지 않게 한다. 캔버스·표만 국소 스크롤을 허용한다.

### 4.4 아이콘

- 시스템 아이콘은 24px 기준, 16·20·24·32·40px 사용.
- 선 두께는 24px 기준 1.6px, 1.5~2px 범위.
- SVG 사용.
- 아이콘과 인접 배경은 기본 3:1, 선명한 화면 모드 7:1.
- 텍스트와 함께 쓸 때 중앙 정렬.
- 같은 크기에서는 한 가지 두께만 사용.
- 아이콘만 있는 버튼에는 접근 가능한 이름을 제공한다.

출처: [KRDS 아이콘](https://www.krds.go.kr/html/site/style/style_06.html), [KRDS 버튼](https://www.krds.go.kr/html/site/component/component_05_02.html).

**우리 적용 제안**

- Lucide(ISC) 또는 직접 만든 SVG를 쓴다. 상용 제품 아이콘을 복제하지 않는다.
- 상태 아이콘은 색과 무관하게 모양이 달라야 한다(체크, 느낌표, 물음표, 사각형 등).
- 아이콘만 있는 “더보기”, “닫기”, “삭제”에는 한국어 접근 이름을 붙인다.

### 4.5 선명한 화면 모드

KRDS는 일반 모드와 별도로 고대비 “선명한 화면 모드”를 제공한다.

- 어두운 배경, 밝은 전경.
- 본문 15:1 이상, 제목·레이블 7:1 이상, 아이콘·시각 보조 4.5:1 이상.
- 레이어가 쌓일수록 배경이 밝아진다.
- 버튼·입력·링크의 윤곽선을 더 굵게, 링크 밑줄을 표시한다.
- 일반 모드와 동일한 정보·기능을 제공해야 한다.
- 래스터 이미지는 모드별 대체 이미지를 준비하거나, 두 모드에서 모두 읽히는 이미지를 쓴다.

출처: [KRDS 선명한 화면 모드](https://www.krds.go.kr/html/site/style/style_09.html).

**우리 적용 제안**

- 사용자 설정에 “고대비 화면”을 두고, 선택을 저장한다.
- 모든 화면을 고대비로 QA한다. 특히 배치 캔버스의 격자·선택 상태·경고, 표의 선택 행, 미리보기 위 오버레이.
- 이미지 썸네일 위에 상태 배지를 얹을 때 고대비에서도 읽히는지 확인한다.

### 4.6 디자인 토큰

KRDS는 primitive, semantic, mode, responsive 토큰을 제공한다. 색·타이포·간격·반경·그림자를 토큰으로 관리하고, 고대비·반응형 모드 전환에 쓴다.

출처: [KRDS 디자인 토큰](https://www.krds.go.kr/html/site/style/style_07.html).

**우리 적용 제안**

- 최소 토큰: color, typography, spacing, radius, border, shadow, focus, status.
- 하드코딩된 색·간격을 금지하고 CSS 변수로 관리한다.
- 고대비 모드는 같은 semantic 토큰의 다른 값으로 구현한다.
- 토큰 이름에 “primary”, “danger” 같은 의미를 부여하고, 실제 색 이름은 primitive에만 둔다.

## 5. 컴포넌트와 패턴

### 5.1 공통 탐색

- 건너뛰기 링크를 문서 첫 요소로 제공한다.
- 헤더·사이드 메뉴를 nav로 표시하고 적절한 이름을 준다.
- 현재 페이지는 aria-current="page"로 표시한다.
- 메뉴는 키보드로 탐색하고, 하위 메뉴 확장 상태를 aria-expanded로 알린다.
- 축소된 메뉴의 링크는 보조기술에서 접근되지 않게 한다.
- 사이드 메뉴는 2단계 이내, 좁은 화면에서는 햄버거 메뉴로 전환한다.

출처: [KRDS 사이드 메뉴](https://www.krds.go.kr/html/site/component/component_03_04.html), [KRDS 메인 메뉴](https://www.krds.go.kr/html/site/component/component_03_02.html).

### 5.2 버튼

- 모든 버튼에 접근 가능한 이름을 제공한다.
- 버튼 레이블은 동사형으로 쓴다. “확인”보다 “이대로 송출”, “이미지 올리기”.
- 한 화면에 최상위 강조 버튼은 하나만 둔다.
- 같은 그룹의 버튼은 같은 크기로 한다. 중요도는 크기가 아니라 스타일로 구분한다.
- 수직 배치 시 가장 중요한 버튼을 위에 둔다.
- 아이콘은 중요한 작업에만, 텍스트 레이블과 의미가 맞을 때 쓴다.
- 제출 버튼은 중복 클릭을 무시한다.
- 마우스 17×17px, 터치 44×44px 이상의 반응 영역을 권장한다.
- 포커스 링은 인접 배경과 3:1 이상, 숨기지 않는다.

출처: [KRDS 버튼](https://www.krds.go.kr/html/site/component/component_05_02.html).

### 5.3 입력 폼

- 모든 입력에 레이블을 제공한다. 플레이스홀더를 레이블 대체로 쓰지 않는다.
- 필수·선택을 일관되게 표시한다. 대부분이 필수면 선택만, 대부분이 선택이면 필수만 표시한다.
- 단위(초, MB, px)를 레이블과 별도로 표시한다.
- 도움말은 입력란 가까이에 둔다.
- 한 열 세로 정렬을 기본으로 한다.
- 제출 버튼은 오른쪽 아래, 취소·보조는 그 왼쪽.
- 서버 검증과 클라이언트 검증을 함께 쓴다.
- 오류 시 입력값을 지우지 않는다.
- 오류가 발생한 첫 항목으로 초점을 이동한다.
- 필드 간 이동을 자동으로 강제하지 않는다.
- 반복 입력은 자동 완성·이전 값 재사용을 제공한다.

출처: [KRDS 입력 폼](https://www.krds.go.kr/html/site/global/global_08.html), [KRDS 텍스트 입력](https://www.krds.go.kr/html/site/component/component_09_03.html).

**우리 적용 제안**

- 장소명, 모니터 이름, 이미지 표시 시간, 재생 모드처럼 한 화면에 한 결정만 둔다.
- “필수” 표시는 텍스트로 한다. 별표만 쓰지 않는다.
- 저장 버튼은 항상 보이게 하고, 자동 저장은 “초안 저장됨”으로 알린다.
- 셀렉트 변경만으로 폼을 제출하지 않는다. 사용자가 “적용”을 누르게 한다.

### 5.4 표

- 실제 데이터 표는 table, caption, thead, th, tbody를 사용한다.
- th에 scope를 지정해 읽는 방향을 정한다.
- 열 수를 최소화한다.
- 열 구분선은 꼭 필요할 때만 쓴다.
- 숫자·용량·퍼센트는 오른쪽, 텍스트·날짜·IP는 왼쪽 정렬한다.
- 빈 셀은 비워두지 않고 “-”를 표시한다.
- 데이터가 많으면 정렬·검색·필터를 제공한다.
- 작은 화면에서는 단순 표를 세로로 풀거나, 복잡한 표는 가로 스크롤과 고정 헤더를 제공한다.
- 레이아웃을 위해 표를 쓰지 않는다.

출처: [KRDS 표](https://www.krds.go.kr/html/site/component/component_04_11.html), [KRDS 목록 탐색](https://www.krds.go.kr/html/site/global/global_04.html).

**우리 적용 제안**

- 모니터 표: 이름, 해상도, 방향, 마지막 연결, 상태, 현재 이미지. 7열 이내.
- 이미지 표: 썸네일, 파일명, 해상도, 비율, 사용처, 업로드일. 6열 이내.
- 감사 로그 표: 시각, 사용자, 작업, 대상, 결과. 상세는 행 확장이나 상세 패널로.
- 표의 행 전체를 클릭 가능하게 만들지 않는다. 이름 링크나 “열기” 버튼을 둔다.

### 5.5 오류

KRDS 오류 패턴의 원칙:

- 빠르게 인지할 수 있게 표현한다.
- 어떤 오류가 어디서 발생했는지 분명히 설명한다.
- 수정 방법을 제공한다.
- 정중한 문체를 쓴다.
- 인라인 메시지 또는 모달을 쓴다.
- 오류가 발생한 요소로 초점을 이동한다.
- 사용자가 입력한 값을 유지한다.

출처: [KRDS 오류](https://www.krds.go.kr/html/site/global/global_07.html).

**우리 문구 형식**

- 원인: “이미지 비율이 모니터와 맞지 않습니다.”
- 다음 행동: “세로 이미지를 올리거나, ‘맞춤’을 ‘잘라서 채우기’로 바꿔 주세요.”
- 복구: “다시 검사”, “다른 이미지 선택”.

피해야 할 문구:

- “오류가 발생했습니다.”
- “잘못된 값입니다.”
- “관리자에게 문의하세요.”
- “Error 500”.

**오류 요약**: KRDS는 인라인·모달을 예시로 제공한다. 긴 관리 폼에서는 상단에 오류 요약(항목명 + 링크)을 추가하고, 첫 오류로 초점을 이동하는 것이 WCAG 3.3.1·3.3.3과 프로젝트 기준에 부합한다. 이는 KRDS가 직접 규정한 컴포넌트가 아니라 우리의 보강 제안이다.

### 5.6 모달

- 모달은 최후의 수단이다. 다단계 프로세스·복잡한 폼은 별도 화면으로.
- 확인·오류·짧은 정보에만 쓴다.
- 제목·설명·본문·푸터를 명확히 한다.
- 푸터의 확인·취소 버튼은 항상 보이게 한다.
- 열릴 때 모달 또는 첫 상호작용 요소로 초점을 이동한다.
- 모달 밖으로 초점이 나가지 않게 한다.
- ESC로 닫는다.
- 닫기 버튼은 DOM의 가장 마지막에 둔다.
- 닫으면 연 버튼으로 초점을 돌린다.
- 자동으로 모달을 띄우지 않는다. 세션 만료·긴급 정보는 예외.

출처: [KRDS 모달](https://www.krds.go.kr/html/site/component/component_04_05.html), [KRDS 확인](https://www.krds.go.kr/html/site/global/global_11.html).

**우리 적용 제안**

- “이대로 송출” 확인 모달: 장소, 모니터 수, 이미지 수, 모드, 버전, 경고를 요약.
- “이미지 삭제” 확인 모달: 사용 중인 장소와 대체 이미지 영향을 표시.
- “초안 나가기” 확인 모달: 저장·취소·나가기.
- 다중 파일 업로드는 모달이 아니라 전용 화면.

### 5.7 배지

- 텍스트 레이블을 항상 제공한다.
- 텍스트와 배경은 4.5:1 이상.
- 한 항목에 배지 하나.
- 배지를 링크·버튼으로 만들지 않는다.
- 주요 색을 배지 배경으로 쓰지 않는다. 버튼으로 오인될 수 있다.

출처: [KRDS 배지](https://www.krds.go.kr/html/site/component/component_04_06.html).

**우리 적용 제안**

- 상태 배지: “온라인”, “오프라인”, “대기”, “오류”. 색+아이콘+글자.
- “송출 중”, “초안”, “승인 대기”, “반려”는 배지로 구분하되, 상세와 다음 행동은 별도로 표시한다.
- 경고 배지에 숫자만 쓰지 않는다. “주의 3”처럼 의미를 붙인다.

### 5.8 단계 표시기

- 여러 단계의 입력·중간 저장이 필요할 때 쓴다.
- 각 단계는 논리적·선형 관계여야 한다.
- 완료/진행률을 표시한다.
- 단순한 폼에는 쓰지 않는다.
- 숙련자는 단계를 건너뛰거나 빠른 교체를 선택할 수 있게 한다.

출처: [KRDS 단계 표시기](https://www.krds.go.kr/html/site/component/component_07_01.html), [KRDS 입력 폼](https://www.krds.go.kr/html/site/global/global_08.html).

**우리 적용 제안**

- 첫 송출 6단계에만 단계 표시기를 쓴다.
- 빠른 교체 3단계는 별도 표시기를 쓴다.
- “1/6 장소 만들기”처럼 단계 이름을 함께 보여준다.
- 이전 단계로 돌아가도 입력값을 유지한다.

### 5.9 도움 패널·맥락 도움말

- 도움 패널은 개념·용어·옵션 설명·이용 방법을 담는 사이드 패널이다.
- KRDS는 화면 로딩 시 도움 패널을 열린 상태로 제공하라고 권한다.
- 아이콘 버튼은 44×44px 이상을 고려한다.
- 패널이 열리면 패널로 초점을 이동하고, 닫으면 연 버튼으로 돌린다.
- 필수 정보를 도움 패널에만 숨기지 않는다.
- 맥락 도움말과 도움 패널을 같은 과업 흐름에서 동시에 쓰지 않는다.

출처: [KRDS 도움 패널](https://www.krds.go.kr/html/site/component/component_08_01.html), [KRDS 맥락적 도움말](https://www.krds.go.kr/html/site/component/component_08_03.html).

**우리 적용 제안**

- 첫 방문·첫 송출에서만 도움 패널을 자동으로 연다. 반복 사용자는 닫힘 상태를 기억한다.
- 패널 내용은 “이 화면에서 할 일”, “용어”, “자주 막히는 곳”, “관련 화면” 순서.
- 스크린샷은 우리 제품 화면만 쓴다. 상용 제품 캡처를 넣지 않는다.
- 1~2문장으로 짧게 쓰고, 긴 설명은 “자세히 보기”로 분리한다.

### 5.10 파일 업로드

- 레이블·설명·허용 형식·용량·개수 안내를 제공한다.
- 드래그 앤 드롭과 파일 선택 버튼을 함께 제공한다.
- 파일 선택 버튼은 업로드 후에도 다시 사용할 수 있게 한다.
- 업로드 중·완료·오류 상태를 표시한다.
- 오류는 “형식”, “용량”, “빈 파일”, “개수 초과”, “업로드 실패”로 구분한다.
- 파일명이 길면 말줄임표를 쓰고 두 줄로 늘리지 않는다.
- 다중 파일 업로드를 모달에 넣지 않는다.
- 사용자가 제출하기 전에 자동으로 서버에 저장하지 않는다.
- 이미지 용량 제한이 있으면 자동 압축을 고려한다.

출처: [KRDS 파일 업로드](https://www.krds.go.kr/html/site/component/component_09_04.html).

**우리 적용 제안**

- “이미지 올리기” 화면은 업로드 → 검사 → 미리보기 → “보관함에 추가” 순서.
- 허용 형식은 JPEG·PNG·WebP. GIF·동영상은 MVP 제외.
- 파일 선택 즉시 픽셀·비율·용량을 읽고, 통과/경고/거부를 카드로 보여준다.
- EXIF를 제거하고, 필요하면 화면용 변환본을 만든다.
- 같은 파일은 체크섬으로 중복 안내.
- “송출”은 별도 단계에서만 한다.

### 5.11 확인

- 취소하기 어렵거나 결과가 중요한 행동에만 확인을 요청한다.
- 무엇이 일어나는지 명확하고 간결하게 설명한다.
- 확정·취소 버튼을 모두 제공한다.
- 버튼 레이블에 행동을 구체적으로 쓴다(“삭제”가 아니라 “이미지 삭제”).
- 중요도가 낮은 행동에 반복 확인을 붙이지 않는다.

출처: [KRDS 확인](https://www.krds.go.kr/html/site/global/global_11.html).

**우리 적용 제안**

- 송출, 삭제, 권한 변경, 복구에만 확인을 쓴다.
- “저장”에는 확인 모달을 쓰지 않고 저장 상태만 알린다.
- 송출 확인에는 경고 요약과 “이대로 송출” 버튼을 둔다.

## 6. 문구 작성

KRDS 공개 페이지에서 독립된 “글쓰기” 장을 확인하지 못했다. 문구 지침은 오류·버튼·알림·폼·확인 패턴에 흩어져 있다. 우리는 그 원칙을 다음과 같이 통합한다.

### 6.1 기본 원칙

- 사용자가 지금 무엇을 해야 하는지 한 문장으로 쓴다.
- “핵심 동사 + 목적지” 구조를 쓴다. 예: “이미지 3장을 4번 화면에 송출합니다.”
- 수식·감탄·홍보성 표현을 배제한다.
- 전문 용어는 첫 등장 시 쉬운 말 + 괄호 병기.
- 같은 행동은 같은 단어를 쓴다. “송출/게시/배포”를 섞지 않는다.
- 오류는 정중하게, 원인과 다음 행동을 함께 쓴다.
- 민감정보를 문구에 직접 노출하지 않는다. 필요하면 마스킹한다.
- 숫자와 단위를 함께 쓴다. “10초”, “3장”, “4대”, “1920×1080”.
- 날짜는 “2026년 11월 24일 14:30”처럼 연·월·일·시각을 분명히 쓴다.

### 6.2 화면별 문구 예

| 상황 | 좋은 문구 | 피할 문구 |
|---|---|---|
| 첫 화면 | “첫 장소를 만들어 보세요. 6단계면 첫 송출을 마칠 수 있습니다.” | “사이트를 생성하세요.” |
| 화면 등록 | “같은 네트워크에서 기다리는 모니터를 찾았습니다. 이 모니터를 이 장소에 추가할까요?” | “디바이스 페어링” |
| 이미지 검사 | “이미지가 가로 1920×1080입니다. 세로 모니터에는 위아래 여백이 생깁니다.” | “해상도 부적합” |
| 재생 모드 | “순환 동기화 — 모든 모니터가 같은 시각에 다음 이미지로 넘어갑니다.” | “동기화 스케줄 모드” |
| 미리보기 | “4대 중 1대가 오프라인입니다. 마지막 이미지를 계속 보여줍니다.” | “디바이스 오프라인” |
| 송출 확인 | “A 안내데스크 4대에 이미지 3장을 순환 송출합니다.” | “게시하시겠습니까?” |
| 저장 | “초안을 저장했습니다. 나중에 이어서 할 수 있습니다.” | “저장 완료” |
| 오류 | “서버에 연결하지 못했습니다. 네트워크 케이블을 확인한 뒤 ‘다시 연결’을 눌러 주세요.” | “연결 오류” |
| 삭제 | “이미지 2장이 3개 장소에서 사용 중입니다. 삭제하면 해당 화면이 ‘콘텐츠 없음’으로 바뀝니다.” | “삭제하시겠습니까?” |

### 6.3 알림 문구

KRDS 알림 패턴은 “핵심 동사+목적지”, 한 문장, 홍보성 표현 배제, 민감정보 마스킹을 권한다.

출처: [KRDS 모바일 알림](https://www.krds.go.kr/html/site/global/global_12.html).

**우리 적용 제안**

- 저장·송출·오류는 aria-live로 알린다.
- 토스트만으로 끝내지 않고, 중요 상태는 화면 안의 상태 영역에도 남긴다.
- “송출되었습니다”보다 “A 안내데스크 4대에 송출했습니다”처럼 대상을 포함한다.
- 오류 토스트에는 “자세히” 링크를 두어 오류 패널로 이동한다.

## 7. KWCAG 2.2 접근성 체크

KWCAG 2.2는 4개 원칙과 33개 검사항목으로 구성된다. 아래는 우리 관리자 화면에 직접 관련된 항목과 구현 기준이다.

| KWCAG 2.2 항목 | 우리 화면에서의 의미 | 확인 방법 |
|---|---|---|
| 적절한 대체 텍스트 제공 | 썸네일, 상태 아이콘, 차트, 로고에 적절한 alt 또는 aria-label | 스크린 리더로 이미지·아이콘 탐색 |
| 표의 구성 | 모니터·이미지·로그 표에 caption, thead, th scope | 표만 탐색해도 행·열 의미 파악 |

| 명확한 지시사항 제공 | 업로드 형식·용량, 필수 항목, 재생 모드 설명 | 도움말 없이 과업 완료 |

| 정지 기능 제공 | 미리보기 자동 재생·대시보드 자동 갱신 정지 | 정지 버튼 |
| 깜빡임과 번쩍임 제한 | 전환 효과·경고 애니메이션 | 초당 3~50회 금지 |
| 반복 영역 건너뛰기 | 건너뛰기 링크 | 첫 Tab |

| 오류 정정 | 원인·위치·수정 방법, 첫 오류로 초점 | 잘못된 값 제출 |
| 반복 입력 정보 | 같은 설정을 다른 모니터에 복사 | 반복 입력 횟수 |

| 웹 애플리케이션 접근성 준수 | 커스텀 위젯에 role·상태·키보드 | 위젯별 키보드 테스트 |

KWCAG 2.2의 추가·강화 항목 중 우리 화면에 특히 중요한 것:

- **문자 단축키**: 단일 문자 단축키를 끄거나, 수식키와 조합하거나, 포커스가 있을 때만 작동하게 한다.
- **고정된 참조 위치 정보**: 전자출판형 문서를 웹으로 제공할 때 페이지 위치를 일관되게 유지한다. 우리 관리자 화면에는 직접 해당하지 않지만, 매뉴얼 뷰어를 만들 때 참고한다.
- **단일 포인터 입력 지원**: 드래그 앤 드롭은 반드시 “위로/아래로” 버튼이나 파일 선택 버튼 같은 단일 포인터 대안을 제공한다.
- **포인터 입력 취소**: 드래그 중 ESC·포인터 해제로 취소할 수 있게 한다.
- **레이블과 네임**: 화면에 보이는 텍스트와 접근 가능한 이름이 일치해야 한다. “저장” 버튼의 aria-label을 “제출”로 바꾸지 않는다.
- **동작기반 작동**: 기기 흔들기·카메라 동작으로만 작동하는 기능을 만들지 않는다. 만들면 UI 대안과 끄기 설정을 제공한다.
- **찾기 쉬운 도움 정보**: 도움말·문의·매뉴얼을 일관된 위치에 둔다.
- **검증 기능 인증**: 자동 입력·캡차·인증이 있으면 접근 가능한 대안을 제공한다.
- **반복 입력 정보**: 이전 단계·다른 모니터의 설정을 재사용할 수 있게 한다.

## 8. 공공기관 제약

다음은 법령이 모든 기관에 동일하게 요구하는 문구가 아니라, 우리 프로젝트의 요구와 공공기관 운영 관행을 함께 정리한 것이다. 실제 적용 범위는 기관의 정보보호·개인정보·기록물 담당 부서와 확인한다.

### 8.1 승인 흐름

- 작성자·검토자·송출자·관리자 역할을 구분한다.
- 초안 → 검토 요청 → 승인/반려 → 송출 → 이력 순서.
- 승인자는 변경 요약(장소, 모니터, 이미지, 모드, 경고, 버전)을 본다.
- 긴급 송출은 사유를 남기고 사후 승인할 수 있다.
- 작은 조직에서는 역할을 겸할 수 있지만, “누가 승인했는가”는 기록한다.

### 8.2 감사 로그

- 로그인, 업로드, 수정, 삭제, 승인, 송출, 복구, 권한 변경, 모니터 등록·해제를 남긴다.
- 시각, 사용자, 역할, 작업, 대상, 변경 전후, 결과, IP(필요 시 마스킹).
- 추가 전용, 수정·삭제 불가.
- 기간·사용자·작업으로 필터, CSV 내려받기.
- 서버 시각은 내부 NTP로 맞춘다.

### 8.3 개인정보 최소화

개인정보 보호법 제3조는 처리 목적에 필요한 최소한의 개인정보만 수집하고, 목적 외로 이용하지 않으며, 안전하게 관리하도록 한다. 제16조는 최소 수집과 입증 책임을, 제29조는 접속기록 보관 등 안전성 확보 조치를 규정한다.

출처: [개인정보 보호법](https://www.law.go.kr/%EB%B2%95%EB%A0%B9/%EA%B0%9C%EC%9D%B8%EC%A0%95%EB%B3%B4%EB%B3%B4%ED%98%B8%EB%B2%95).

**우리 적용**

- 관리자 계정: 이름, 아이디, 역할, 상태만. 주민번호·연락처·생년월일은 받지 않는다.
- 이미지 EXIF 제거.
- 관람객 분석·카메라·얼굴 인식 없음.
- 접속 IP는 필요 시 마스킹·단기 보존.
- 외부 분석 도구·폰트 CDN·아이콘 CDN 없음.

### 8.4 외부 클라우드 미의존

- 서버·DB·이미지 저장소·폰트·아이콘·라이브러리를 원내에서 호스팅한다.
- 런타임에 외부 URL을 호출하지 않는다. CSP로 외부 연결을 차단한다.
- 업데이트는 서명된 패키지 또는 내부 배포로.
- 오프라인 캐시·재부팅 복구·내부 NTP.
- 클라우드 CMS를 쓰지 않는다는 뜻이며, 외부 백업·재해복구 수단은 기관 정책에 따라 별도 검토한다.

### 8.5 안정성·보안

전자정부법 제56조는 정보통신망과 행정정보의 안전성·신뢰성 확보를 위한 보안대책을, 제56조의2는 정보시스템 장애 예방·대응·복구를 규정한다.

출처: [전자정부법](https://www.law.go.kr/%EB%B2%95%EB%A0%B9/%EC%A0%84%EC%9E%90%EC%A0%95%EB%B6%80%EB%B2%95).

**우리 적용**

- 업로드 검사: 확장자·MIME·매직바이트·픽셀·용량·압축 폭탄.
- 이미지 재인코딩, SVG·HTML 업로드 차단.
- 세션 만료, 최소 권한, CSRF, 감사 로그, 백업·복구 리허설.
- 플레이어 자동 시작·watchdog·절전 해제·NTP.

### 8.6 웹 접근성 법적 맥락

장애인차별금지 및 권리구제 등에 관한 법률 제20조는 정보접근에서의 차별을 금지하고, 제21조는 정보통신·의사소통에서 장애인이 동등하게 접근·이용할 수 있도록 정당한 편의를 제공하도록 한다.

출처: [장애인차별금지 및 권리구제 등에 관한 법률](https://www.law.go.kr/%EB%B2%95%EB%A0%B9/%EC%9E%A5%EC%95%A0%EC%9D%B8%EC%B0%A8%EB%B3%84%EA%B8%88%EC%A7%80%EB%B0%8F%EA%B6%8C%EB%A6%AC%EA%B5%AC%EC%A0%9C%EB%93%B1%EC%97%90%EA%B4%80%ED%95%9C%EB%B2%95%EB%A5%A0).

접근성은 “있으면 좋은 기능”이 아니라 공공 서비스의 기본 조건으로 다룬다.

## 9. 데스크톱 관리자에 적용할 것과 적용하지 않을 것

### 9.1 그대로 적용

- 타이포그래피 원칙: 17px 기본, 150% 이상 줄 간격, 400·700 중심.
- 명도 대비: 본문 4.5:1, 큰 글자·UI 3:1, 고대비 모드.
- 키보드·포커스·건너뛰기 링크.
- 레이블·필수/선택·도움말·오류 정정.
- 표의 caption·thead·th scope, 숫자 오른쪽 정렬, 빈 셀 “-”.
- 버튼 동사형 레이블, 한 화면 한 개의 주요 버튼.
- 모달 포커스 트랩·ESC·복귀.
- 파일 업로드의 형식·용량 안내, 드래그+파일 선택, 구체적 오류.
- 8pt 간격, 24px 화면 여백.
- 배지의 텍스트·대비·비상호작용 원칙.

| 1200px 최대 콘텐츠 폭 | 폼·읽기 화면은 1200px, 배치·스케줄·미리보기는 전체 폭 |

| 모바일 우선 브레이크포인트 | 데스크톱 우선, 1024·768은 축소·상태 확인용 |
| 도움 패널 기본 열림 | 첫 방문·첫 송출에서만 열림, 이후 기억 |
| 서비스 패턴 5종 | 로그인·도움·오류·확인만 차용, 방문·검색·신청 여정은 미적용 |
| 고대비 모드 | 선택형, 사용자 설정에 저장 |
| 정부 표준 배지 색 | 기관 색으로 조정하되 의미·대비 유지 |

### 9.3 적용하지 않음

- 공식 정부 배너(Masthead), 운영기관 식별자, 정부 상징·로고. 내부 관리 도구에 정부 공식 서비스 배너를 붙이면 공식 서비스로 오인될 수 있다. 기관의 승인 없이 사용하지 않는다.
- 국민 대상 서비스 여정(방문·검색·신청·정책 정보 확인)을 그대로 복제하는 것.
- 마케팅용 대형 디스플레이 타이포그래피.
- 공공 누리집의 푸터·개인정보 처리방침 문구를 그대로 복사하는 것. 기관의 실제 정책을 써야 한다.
- KRDS 구성 요소를 “우리 것이 원래 KRDS”처럼 재배포하는 것.
- 고대비 모드를 모든 사용자에게 강제하는 것.
- 모바일에서 복잡한 배치 편집을 억지로 제공하는 것.

## 10. 화면별 실무 체크리스트

### 홈

- [ ] 전체 화면 수, 온라인, 주의 필요, 오늘 송출 상태를 첫 화면에.
- [ ] 장소 카드: 이름, 모니터 수, 상태, 현재 이미지 썸네일, 마지막 송출, “미리보기”, “이미지 바꾸기”.
- [ ] “다음 할 일”: 오프라인, 비율 경고, 미게시 초안, 새 화면.
- [ ] 최근 활동: 누가, 언제, 무엇을.
- [ ] 빈 상태: “첫 장소 만들기” 큰 버튼.
- [ ] 자동 갱신 시 정지·새로고침 버튼, aria-live는 과도하게 울리지 않게.

### 장소 목록

- [ ] 검색·필터(상태, 장소명), 정렬.
- [ ] 표 또는 카드, 7열 이내.
- [ ] 행 클릭이 아니라 장소명 링크/“열기”.
- [ ] 삭제는 사용 중 모니터·재생안 영향 표시 후 확인.

### 장소 상세·배치

- [ ] 템플릿(1대·가로·세로·격자·직접) 썸네일.
- [ ] 캔버스에 모니터 이름·해상도·방향·상태.
- [ ] 겹침·빈 공간·화면 밖 경고.
- [ ] 드래그·리사이즈·스냅·키보드 미세 조정.
- [ ] 실행 취소/재실행.
- [ ] 우측 패널: 이름, 해상도, 방향, 회전, 맞춤, 테스트 이미지.
- [ ] “다음: 이미지 올리기” 고정 버튼.

### 화면 등록

- [ ] 자동 발견 목록: 6자리 코드, IP, 해상도, 브라우저, “승인”.
- [ ] 코드로 등록, 링크로 등록.
- [ ] 승인 후 장소·이름·방향 확인.
- [ ] 테스트 이미지 전송.
- [ ] capability 배지: 브라우저, 다중 창, 오프라인 캐시, 구형 브라우저.

### 콘텐츠

- [ ] 업로드 전 형식·용량·해상도 안내.
- [ ] 드래그+파일 선택, 진행률, 중복 안내.
- [ ] 카드/목록: 썸네일, 파일명, 크기, 해상도, 비율, 사용처, 업로드일.
- [ ] 상세: 가로/세로 미리보기, 안전 영역, 비율 경고, “다른 이미지로 바꾸기”.
- [ ] 삭제 전 사용 중 장소·모니터 영향.
- [ ] EXIF 제거, 체크섬 중복, 변환본.

### 재생

- [ ] 4개 모드 카드: 개별·순환 동기화·동시·통합. 한 줄 설명+그림.
- [ ] 이미지 순서: 드래그+위/아래 버튼, 표시 시간, 맞춤, 전환.
- [ ] “자동 채우기”: 이미지 수/모니터 수/시작 위치/회전 배분.
- [ ] LCM 패턴 표.
- [ ] 경고: 이미지 없음, 부족, 중복, 시간 0, 합계 불일치.
- [ ] “미리보기” 버튼 고정.

### 미리보기

- [ ] 실제 배치 비율의 가상 모니터.
- [ ] 재생/일시정지, 시간 이동, 배속, 다음 전환까지 남은 시간.
- [ ] 모드·가로/세로·기기 프레임 전환.
- [ ] 경고 패널: 오프라인, 비율, 겹침, 빈 슬롯, 이미지 없음.
- [ ] “이대로 송출” → 요약 → 확인.
- [ ] 미리보기와 실제 송출이 같은 엔진.

### 상태·오류

- [ ] 배지: 온라인·오프라인·대기·오류. 아이콘+글자+색.
- [ ] 상세: 마지막 연결, 현재 이미지, 버전, 해상도, 방향, 네트워크, 오류 코드, 로그 복사.
- [ ] 복구: 다시 연결, 테스트 이미지, 플레이어 재시작, 로그 복사.
- [ ] 오프라인 시 마지막 콘텐츠 재생 안내.
- [ ] 오류 문장은 원인+다음 행동.
- [ ] 오류 요약과 첫 오류 초점.

### 설정

- [ ] 사용자·역할: 최소 권한, 역할 설명.
- [ ] 감사 로그: 필터, CSV, 추가 전용.
- [ ] 서버·백업: 마지막 백업, 복구 리허설.
- [ ] 세션 만료 경고·연장.
- [ ] 개인정보 처리방침·이용약관 링크(기관 실제 문서).

## 11. 반응형 동작

| 폭 | 레이아웃 | 가능한 작업 |
|---|---|---|
| 1280px 이상 | 사이드 메뉴 + 캔버스 + 속성 패널 | 전체 편집·미리보기·송출 |
| 1024~1279px | 사이드 메뉴 접힘, 속성 패널 축소 | 배치·재생 편집, 표 가로 스크롤 |
| 768~1023px | 메뉴 드로어, 속성 패널 하단 시트 | 상태 확인, 간단한 순서 변경, 미리보기 |
| 768px 미만 | 단일 열, 카드 중심 | 상태 확인, 긴급 공지, 빠른 교체 |

- 200% 확대에서 텍스트가 잘리지 않아야 한다.
- 400% 리플로우에서 페이지 전체 가로 스크롤이 생기지 않게 한다. 캔버스·표만 국소 스크롤.
- 고정 높이·고정 px 줄 간격을 피한다.
- 터치 환경에서는 44×44px 이상.
- hover에만 의존하는 도움말·액션을 만들지 않는다.

## 12. 라이선스·출처 요약

KRDS의 모든 자료는 **공공누리 제1유형(출처표시)**으로 제공된다. 상업적·비상업적 이용, 변경·2차적 저작물 작성·배포가 허용되며, 출처를 표시해야 한다.

공식 출처 표기 예시:

> 본 저작물은 행정안전부에서 2024년 작성하여 공공누리 제1유형으로 개방한 ‘범정부 UI/UX 디자인시스템(KRDS)’을 이용하였으며, 해당 저작물은 ‘KRDS 디자인시스템 홈페이지(www.krds.go.kr)’에서 무료로 다운받으실 수 있습니다.

출처: [KRDS 저작권정책](https://www.krds.go.kr/html/site/utility/utility_06.html) — 2025-05-13 최종 수정.

주의할 점:

- KRDS 사이트의 저작권정책은 “모든 자료”를 공공누리 제1유형으로 설명한다.
- GitHub HTML 컴포넌트 킷의 package.json은 license를 ISC로 표시한다.
- README는 “KRDS 이용약관”을 따르라고 안내한다.
- 따라서 코드를 재사용할 때는 **KRDS 출처 표기 + ISC 고지 + 포함된 제3자(Swiper MIT 등) 고지**를 모두 보수적으로 유지한다.
- 정부 상징·공식 배너·운영기관 식별자는 저작권과 별개로 공식 서비스 오인 방지 문제가 있다. 내부 관리 도구에는 기관 승인 없이 쓰지 않는다.

폰트·아이콘·오픈소스 자산의 전체 목록과 허용 범위는 [licenses.md](licenses.md)에 정리했다.
